# Coffer 文档风格指南

> 仓库级风格规范，适用于 docs/ 各篇。全局原则见 `~/.claude/rules/common/doc-style.md`（8 条核心规则 + 适用判定 + 自检清单）——本文档不重复全局规则，只做本仓库的术语定名、硬规则裁决与重构操作规约。
> 基准：NASA KSC-DF-107 Rev F《Technical Documentation Style Guide》（逐条映射分析见 `.omc/artifacts/nasa-ksc-df107-rules.md`，运维产物不入库）。

## 1. 定位与适用判定

- **适用**：docs/ 下一切技术文档——需求、架构、设计、验收判据、实现方案、交接记录、帮助中心技术内容，以及 README、CLI 说明、提交信息中的技术表述。
- **不适用**：文章、散文、叙事、营销文案、对话回复。判定口诀与全局规则一致：写给人「用」的文档用本标准，写给人「读」的文章不用。
- 本仓文档按「写给人用」起草：一遍读懂即可执行、可验收、可判定。

## 2. 本仓术语表（权威定名）

> 以代码（core/、macos/）与 docs 高频用法为准，逐词 grep 验证。同一事物全文用同一词；改术语须全局联动并在修订记录登记。

| 术语 | 定名 | 说明 |
| --- | --- | --- |
| 密码库（Vault） | **密码库** | 条目的逻辑容器，一个 App 可含多个、各自独立加密。早期需求文档术语表定义「保险库（Vault）」，文档内保持一致即可；**新写文档统一「密码库」** |
| 主密码 | **主密码** | 唯一必设凭据，经 KDF 派生主密钥；无服务端找回。启用 Touch ID 解锁或离线恢复码（FR-17，均为 opt-in）后可重设主密码 |
| 环境容器 | **环境容器** | 带 `coffer:environment` 标签的安全笔记条目，`set-env` 的写入目标 |
| MCP | **MCP** | Model Context Protocol；首次出现写全称，此后用缩写 |
| MCP 服务器 | **MCP 服务器** | `coffer mcp` 启动的本地只读服务（无写工具，密码不触模型） |
| MCP 解锁托管 | **MCP 解锁托管** | 解锁密钥存本机钥匙串，CLI / Agent 免密取密的机制（App 设置页开关） |
| 注册（MCP 语境） | **注册** | 把 coffer MCP 服务器登记到 Claude Code（`claude mcp add`）；开关 ON 自动注册（upsert），OFF 自动移除 |
| 判据 | **判据** | 可独立判定成立与否的验收条目（AC-x / TC-x）；判据行用强制句式，建议性表述不得混入 |
| 放置区 | **放置区** | macOS「密码」App 导出 CSV 的暂存目录（用户授权 security-scoped bookmark；导入期间目录只读，由代码纪律保证） |
| 无外部网络 | **无外部网络（数据不出本机）** | 零网络承诺的现行口径（D-4）；本机内 UDS / 回环允许。旧文档「零网络」为同义历史词；**UI 字符串现状仍为「零网络」，属已登记历史词** |
| 序列号（Serial） | **序列号** | 离线签名的授权凭证（Ed25519 签名 + 机器指纹，FR-15），买断制永久有效 |
| 钥匙串（Keychain） | **钥匙串（Keychain）** | macOS 密钥存储；托管 / 生物识别密钥封装存放处。代码侧 Keychain 居多，文档可用中文加括号注 |
| OTA | **OTA** | 用户触发的更新检查 / 下载；仅 4 白名单端点短时 HTTPS（受限豁免，NFR-SEC-08） |
| 修订记录 | **修订记录** | 文档头部版本表；历史行只追加、不改写 |

## 3. 仓库硬规则与 KSC-DF-107 的调和裁决

> 依据：KSC-DF-107 冲突清单 C1–C10 与裁剪项 N1–N12。KSC 原文未覆盖中文场景处，如实标注「标准未明确，本仓约定」。

- **C1 修订记录历史行：只追加、不改写。** 不采纳 KSC §5.3.e(3) 的「吸收为摘要」简写——KSC 物理再版成书、读者拿最新版；本仓是 git 审计链，历史行改写破坏可追溯。新增版本行可采 KSC 描述风格（枚举 + 过去式动词短语 + 句点收尾），但只落在**新行**。
- **C4 交叉引用：锚点非行号。** KSC §3.22.1 佐证（引用一律不附加标题，标签与编号同行）。跨引写章节锚点 / 图号 / 表号 / 判据号；指向列表项落为「§x 第 c 条」文字。
- **C5 中英混排：标准未明确，本仓约定。** ① 英文术语形态全文一致（Coffer、CLI、GitLab 等官方写法）；② 界面文案、按钮、错误文案与代码字符串逐字一致，不意译；③ 中文标点按 GB/T 15834，中西文间不加多余空格；④ 中文标题内嵌英文专名保留官方大小写。
- **情态词规约**（对齐 §3.4 shall / should / will / must）：判据与验收要求用「必须 / 应」，须可验证、无歧义，不得夹带建议；建议用「建议 / 宜」；描述行为事实用「将」；依赖关系用「须」。判据行不混入建议档措辞。**档位注**：判据档「应」在本仓作 MUST 档用（可测试要求），与全局 doc-style.md 的「应当 = SHOULD」不同档，勿混用。
- **语态**（§3.3）：操作步骤用主动 + 祈使（「打开…」「设置…」）；因果归因写明主体（「CLI 返回 1004」，不写「发生错误 1004」）。
- **术语与界面一致**（§3.2 / §3.21.2.f）：以第 2 节术语表与代码字符串为唯一权威。
- **图表纪律**（§3.17 / §3.18）：图先引入后出现（`![]()` 引用即引入）；图题在下、表题在上、表题不进表头；SVG 一律外置 docs/assets/（内联 svg 会被渲染器剥除）。
- **强调只用粗体 / 行内代码**（§5.11.f）：不用引号、斜体、下划线模拟强调。
- **公共文档默认英文（国际化运营口径）。** GitHub 默认展示的对外公共文档一律英文：`README.md`、`CONTRIBUTING.md`、`SECURITY.md`、`CODE_OF_CONDUCT.md`、`CLA.md`、`FEATURES.md`、`docs/README.md`、`macos/README.md`、`android/README.md`、`.github/` 的 Issue / PR 模板。中文版另存同名 `*.zh.md`，两版顶部互相链接（英文 `**[中文](X.zh.md)`**，中文 `**[English](X.md)`**）。英文页正文不得出现中文，路径与中文文件名除外；内部设计文档（`docs/01`–`05`、`docs/DESIGN.md`）仍为中文，不在此列。门禁：`tools/check_docs_facts.sh` ⑦。
- **不引入**：NASA 文档编号体系、封面 / 签名页、字体字号排印、修订字母制（A/B/C）与 Change 竖线、芝加哥 / MLA 参考文献体系（本仓用链接 + 锚点自有体系）。详见裁剪项 N1–N12。

## 4. 重构操作规程（改在用文档）

1. 改前先核前提：按修订记录 md5 + 锚点核对现状，不凭行号断言内容（行号随编辑漂移）。
2. 修订记录历史行原样保留，绝不改写；本次改动在表末追加新行（r 号顺延）。
3. 一次 PR / commit 只动一个文档单元（含其配套文件），不混入无关改动。
4. 判据编号（FR-x / AC-x / TC-x / NFR-x）、版本号、commit hash、日期、锚点引用一律不动。
5. 术语统一以第 2 节为准；拿不准的表述保留原样并标注，不臆改。
6. 无修订记录表的文档（索引 / README 类）→ 在文末追加「修订注记」块，注明按本文档重构（试点 README / docs/README 已用此约定）。
