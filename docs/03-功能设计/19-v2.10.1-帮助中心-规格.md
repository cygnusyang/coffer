## §1 背景与目标

- **背景**：菜单栏「帮助」点开报错。根因——AppKit 把标题为「帮助」的顶级菜单当 `helpMenu` 处理，自动注入系统帮助搜索框；Coffer 未注册 Help Book，空菜单点开即报错。现实现偏离既有架构裁定（`.omc/state/ux-291-arch.md`「`CommandGroup(replacing: .help)`」），实为 `CommandMenu("帮助")`（`CofferApp.swift` `.commands`）。
- **现状帮助面（内容底料）**：`GettingStartedView`（「使用入门」五段）、`ShortcutsSheet`（键盘快捷键三组）、`AboutUpdateSection`（「了解 Coffer」五能力自述）——均为 SwiftUI 静态声明，零网络；帮助无密级，锁定/解锁态均可开。
- **目标**：新增帮助中心（HelpCenter）——完整参考手册（九章超集），作为既有「使用入门」的 canonical 内容源；顺带以 `CommandGroup(replacing: .help)` 修复帮助菜单报错根因（属 dev，不进用户文档）。
- **版本归属**：v2.10.1（帮助中心功能 + 菜单报错根因修复）。

## §2 载体选型

**推荐：SwiftUI 帮助窗口，内容纯 SwiftUI 静态声明。**

- **形态**：新增 `HelpCenterView`（NavigationStack + List(Section)），复用 `GettingStartedView` 的关闭纪律（toolbar `.cancellationAction`「关闭」、Esc 生效）与排版纪律（正文 `.foregroundStyle(.secondary)`）；frame 建议 640×620（九章内容需滚动，List 自带滚动）。
- **内容源**：纯数据 `struct HelpSection { title, rows:[String] }` 静态数组（`HelpCenterContent.swift`），视图 `ForEach` 渲染——与 `GettingStartedView.section(title:rows:)` 同一写法。
- **理由**：
  1. 与既有帮助面零风格偏差——深浅色（语义色）、可访问性（Text/List 原生 VoiceOver + Dynamic Type 缩放）、Esc 关闭全部免费获得；
  2. 零网络天然满足——静态文本无外链、无网络请求；不引入 WebKit / Markdown 解析依赖；
  3. 可逆、非架构级——纯新增窗口 + 菜单项，删菜单项即回退，无迁移成本；
  4. dev team 最顺手——与现行代码范式一致。
- **内容量评估**：九章 × 每节约 4-6 行 ≈ 60 行文案 + 章节标题；`HelpCenterContent` 约 150-200 行 Swift，可控。

**备选（均不推荐，理由从方案 §2）**：

| 载体 | 结论 | 理由 |
| --- | --- | --- |
| Apple Help Book | ✗ 否决 | 需 bundle 结构 + 注册 + 签名配合，深浅色/排版受系统帮助引擎约束，与既有 UI 纪律不一致；仅当未来要系统级帮助搜索才值得，且需用户明示 |
| 纯静态 HTML（WKWebView 宿主） | ✗ 不推荐 | 引入 WebKit 网络面；深浅色与可访问性需额外 CSS/JS 工程；与全 SwiftUI 帮助面风格割裂 |
| `AttributedString(markdown:)` | ○ 远期 | 现版本不引入：markdown 子集支持有限，内容仍为静态常量；未来需集中编辑文案时可无痛升级 |

- **两者并存**：「使用入门」（GettingStartedView）保持简短 primer 不动；「帮助中心」为完整参考（九章超集）。

## §5 正文文案源（九章，与 HelpSection 1:1）

> 转写约定：每小节 = 一个 `HelpSection`；小节标题 = `HelpSection.title`，小节的条目列表 = `rows:[String]`（一条 = 一个字符串，逐条转写零歧义）。例外：§5.4 键盘快捷键含 3 个 `HelpSection`（列表操作 / 条目操作 / 通用），章节标题「键盘快捷键」为 List 分组语义、不单独成 Section（对齐 `ShortcutsSheet` 三组结构）。正文即帮助中心文案源，dev 转写时不得改动措辞 / 键位 / 入口路径。

### 5.1 欢迎使用 Coffer

**HelpSection「欢迎使用 Coffer」**

- Coffer 是本地密码管理器：密码只存在本机，不上传到云端、不做同步（软件更新 OTA 除外）。
- 除软件更新（OTA）外，应用不做任何网络请求，数据始终留在本机。

### 5.2 开始使用

**HelpSection「开始使用」**

- 建库：无密码库时首屏点「创建密码库」，设一个强主密码（3 分以上，共 4 分）。
- 解锁：每次启动 / 锁定后，在锁定页输入主密码，或用 Touch ID 一键解锁。
- 新建条目：解锁后点工具栏「新建」或按 ⌘N，填写名称、用户名、密码。

### 5.3 日常操作

**HelpSection「日常操作」**

- 导入：从其他密码管理器迁入——工具栏「导入」（CSV / 1Password / Bitwarden / OPVault）或 ⌘I / ⌘⇧I。
- 搜索与复制：在主窗口搜索框输入名称后回车直接复制密码；选中条目按 ⏎ 复制其密码。
- 导出备份：工具栏「导出」（或 ⌘E）生成加密备份文件，建议定期保存到安全位置。
- 恢复：换机 / 重装后在首屏点「从备份恢复…」；有既有库时在 设置 → 数据 恢复，锁定态可经「管理密码库…」→「从备份恢复…」直达。
- 多库管理（v2.10.0 新增）：设置 → 数据 →「管理密码库…」查看全部密码库并删除（锁定态可在锁定页「管理密码库…」直达）；删除为不可逆销毁，删除前推荐先导出加密备份（删除不替代备份）。

### 5.4 键盘快捷键（三组）

**HelpSection「列表操作」**

- 上移 / 下移选中 → ↑ / ↓
- 复制选中条目密码 → ⏎
- 搜索框输入名称后回车直接复制 → ⏎

**HelpSection「条目操作」**

- 复制密码 → ⌘⇧C
- 复制用户名 → ⌘U
- 复制验证码 → ⌥⇧C

**HelpSection「通用」**

- 新建条目 → ⌘N
- 锁定 Coffer → ⌘L
- 导入 CSV → ⌘I
- 导入 1Password (.1pux) → ⌘⇧I
- 导出 → ⌘E
- 设置 → ⌘,
- 呼出 / 隐藏主窗口 → ⌥⌘P

> 键位以「动作 → 键位」表达，dev 可按 `ShortcutsSheet` 两列排版渲染（键位等宽 + 次级色），文本内容不变。

### 5.5 备份与恢复

**HelpSection「备份与恢复」**

- 导出加密备份：解锁后工具栏「导出」（或 ⌘E），生成整库加密归档，可用于跨设备迁移与灾后恢复；建议定期保存到安全位置。
- 恢复入口：无既有库时首屏「从备份恢复…」；有既有库时 设置 → 数据 →「从备份恢复…」；锁定态可经锁定页「管理密码库…」→「从备份恢复…」直达。
- 恢复流程：选择 .coffer 备份文件 → 应用先校验（选错 / 损坏 / 版本过新会提示）→ 确认 → 恢复 → 用该库主密码解锁。

### 5.6 安全

**HelpSection「安全」**

- Touch ID：在 设置 → 安全 启用后，解锁与跨库复制可免输主密码。
- 恢复码：忘记主密码时找回数据的唯一途径——在 设置 → 安全 生成并妥善保存，未雨绸缪。
- 修改主密码：在 设置 → 安全 → 修改主密码…（只重新封装密码库头部，不重新加密全部条目）。

### 5.7 MCP / Agent 协作

**HelpSection「MCP / Agent 协作」**

- 让 AI / 自动化安全取用密码：在 设置 → MCP / Agent 协作 开启并注册命令行入口（CLI 与 MCP 均本机运行，数据不出本机）。

### 5.8 常见问题

**HelpSection「常见问题」**

- 忘记主密码怎么办？→ 用恢复码找回（唯一途径）；未生成恢复码则无法找回，请提前在 设置 → 安全 生成并妥善保存。
- Coffer 会把数据上传到云端吗？→ 不会。除软件更新（OTA）外应用不做任何网络请求，可在 设置 → 诊断与隐私 →「网络能力自证…」查看说明与验证方法。
- 软件更新是自动的吗？→ 手动。在「关于 Coffer」中点「检查更新…」主动检查（默认不后台自动检查）。
- 库删除后还能找回吗？→ 未先导出加密备份则不可恢复。删除前应用会推荐先导出备份；日常建议在 设置 → 备份提醒 开启提醒。

### 5.9 故障排查

**HelpSection「故障排查」**

- 解锁提示主密码错误 → 确认主密码正确（区分大小写）；连续输错会出现「N 秒后再试」倒计时，Touch ID 解锁不受该倒计时影响。
- 导入失败 → 核对格式：CSV 须为 1Password 9 列格式；Bitwarden 导入的 passkey 来自真实导出时因私钥为加密形态会被跳过（预检逐条列出原因），条目本体不受影响；密码保护导出当前亦不支持。
- 恢复备份失败 → 核对备份文件：应用会在恢复前校验，非 Coffer 备份 / 文件损坏 / 版本过新会给出具体错误提示，请改选正确的备份文件。

> N4 注记：本节条目均为单行字符串，与 `HelpSection` 扁平 `rows:[String]` 对齐。若未来某条需分步说明，dev 实现时可在该 `HelpSection` 内追加缩进子行表达步骤——**不改 `HelpSection` 数据结构**。

## §8 验收要点与真机判据（含 W2 专项）

**W2 专项：`CommandGroup(replacing: .help)` 预期行为**

- 修复根因：AppKit 将标题为「帮助」的顶级菜单当 `helpMenu` 处理，自动注入系统帮助搜索框；未注册 Help Book 时空菜单点开报错。改 `CommandGroup(replacing: .help)` 后，系统**仍可能**向菜单注入帮助搜索框（注入行为不因替换而完全消除）。
- 预期与判据：点开「帮助」菜单**不报错**；菜单内若出现系统帮助搜索框，**搜索框键入 / 清除不报错、不崩溃**——报错根因的修复实证即「不再报错」，残留搜索框本身不作为失败（真机判据覆盖）。

**真机判据（交用户核销）**

- 点开菜单栏「帮助」菜单：不报错（根因修复实证）。
- 菜单内若有帮助搜索框：键入 / 清除无报错、无崩溃。
- 三入口「键盘快捷键… / 使用入门… / 帮助中心…」均可达、均可打开对应面板。
- 帮助中心渲染：九章正确、滚动正常；深浅色切换无异常；关闭（Esc / 关闭钮）正常；锁定/解锁态均可开、均可用。

**验收要点（dev）**

- 帮助无密级：锁定/解锁态均可开、均可用（对齐 showShortcuts 纪律）。
- 可访问性：全键盘可达、VoiceOver 逐条可读。
- 零网络：内容为静态文本，无外链、无网络请求（grep 无 URL / 网络调用）。
