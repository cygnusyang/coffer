## 0. 结论速览

- **方案**：放置区模式——Coffer 向导一键唤起 macOS「密码」App（Passwords.app）+ 三步指引，用户授权一次「放置区」目录（security-scoped bookmark 持久化），向导打开期间自动检测新导出 CSV → Safari 列映射 → 元数据级去重预览 → 单事务导入。
- **完全自动化不可行**（§1）：苹果刻意设计批量明文导出必须人工触发 + 生物授权，无 API/URL scheme/XPC；Accessibility 自动化已排除（密码管理器申请屏幕控制权限 = 自毁招牌）。
- **容器裁定 M-1（Option A）**：复用 `ImportWizardShell`（`precheckError` Binding 传 nil），S0-S5 在 content 闭包内自持状态机；并列壳方案作废、`ImportWizardShell.swift` 零改动（docs/14 P3 硬约束文件不动）。
- **评审终判**：Warning（0 CRITICAL / 1 HIGH / 3 MEDIUM / 2 LOW）→ HIGH-2 修复后定稿（§6 评审记录）。
- **设计系统沉淀**：DESIGN.md 新增 D-7.5（监视态）、D-8.4（预览层批量选择反馈）、§18 外部目录授权（D-18.1~18.5）。
- **发版门禁**：Passwords.app 导出实样核对（J-5）——本机无法触发人工+Touch ID 导出，未核对前列映射判据 P-2 为 provisional，不得发版。

## 1. 背景与路线论证

### 1.1 苹果锁死链路（为什么是放置区模式）

- macOS「密码」App（Passwords.app，macOS 14+）是 Safari/iCloud 钥匙串密码的**唯一官方批量出口**；其「导出所有密码」被苹果设计为**人工触发 + Touch ID/设备密码验证**后才放行，写入一个明文 CSV。
- **无任何自动化 API**：第三方无法读 iCloud 钥匙串；Accessibility（屏幕控制权限）自动化导出已被项目排除（密码管理器申请屏幕控制权限 = 授人以柄，代价高于收益）。
- 结论：**苹果强制的那一步（人工导出）无法被压缩，只能被引导**。放置区模式的价值 = 把用户的全部动作压成「在 Passwords.app 里点三下 + 一次 Touch ID」，其余（授权目录、打开向导期间检测新文件、列映射、去重、预览、导入、清理提示）全部由 Coffer 接管。

### 1.2 路线②否决记录

`SecItemCopyMatching` 直读 login 钥匙串：只碰旧式通用/互联网密码项（量少，Safari/iCloud 密码已迁入独立「密码」App 第三方读不到）；逐条 ACL 弹窗（50 条 = 50 次「允许」）；沙盒/MAS 审核更严。**不作为主路径**，若做只值调研 spike（未立项）。

### 1.3 安全叙事

人工导出关卡（苹果强制）与 Coffer 自身「批量明文出口需人类显式确认」立场同构：明文 CSV 只在用户显式授权 + 人工导出的前提下进入 Coffer，导入走既有 CSV 面的 R2 纪律（明文只进内存、不落日志、零网络）。

## 4. 交互规格

### 4.1 首次使用流（授权 + 指引）

1. 进入向导（首次 = bookmark 不存在）→ **S0 未授权**态（闭包内 `DropzoneAuthStatusView` `.notAuthorized`）：说明卡 + 建议路径（`~/Downloads/coffer-import`，**仅展示建议，不自动建目录**——自动建目录是隐式副作用，须经面板确认）。
2. **授权范围声明承载于同意界面本身**：S0 说明卡底部**常显**授权声明，并在闭包自开的 NSOpenPanel `message` 字段重申（`config.panelMessage` 有先例）：
   > 「Coffer 将获得对所选目录的**只读**访问，用于自动检测新的密码导出 CSV。仅本地读取、零网络、可随时在『系统设置 › 隐私与安全性 › 文件与文件夹』或本应用内撤销授权。」
   > 声明五要素：**只读 / 目标路径（所选目录）/ 用途（自动检测新导出 CSV）/ 零网络 / 可撤销**。
3. 点「选择放置区目录…」→ 闭包自开 `NSOpenPanel`（`canChooseDirectories = true`，目录多选禁沿用 OPVault 纪律 `OpvaultImportView.swift:125-127`）→ 选定 → 写 **security-scoped bookmark**（`URL.bookmarkData(options: .withSecurityScope)`）持久化（UserDefaults，对齐 clipboardClearSecs 轻量持久化先例）；**选目录动作本身即同意监视**，无二次确认（裁定②/D-18.1）。⚠ **新能力**：`macos/` 当前无任何 security-scoped bookmark 代码（grep 实证），dev-team 需新建；失效/恢复语义 dev-team 实证确认（A-3）。
4. 授权成功 → **S1 已授权·等待新导出**，开始监视。授权粒度 = **只读**。
5. **单写单删（D-18.4）**：bookmark 只由**向导**写入、只由**设置页「移除授权」**删除；移除即广播（向导打开中同步回 `.notAuthorized`）。
6. **作用域全局（D-18.5）**：bookmark 为应用级路径授权，与库无关，切库不产生孤儿授权；S1 明示当前生效目录。

**指引卡（S1 内三步图示）**：

```
① 打开 Passwords.app  →  ② 「文件」菜单 →「导出所有密码」→ 通过验证（Touch ID / 设备密码）
                       →  ③ 保存位置选「放置区目录」→ 存储
```

- 第②步是苹果强制的人工+生物识别步——指引卡明示「这一步必须由你手动完成，Coffer 无法代替」。
- 「打开 macOS 密码 App」按钮：`NSWorkspace.shared.open(/System/Applications/Passwords.app)`。⚠ 沙盒 App 经 open 起外部 App 有历史坑（BUG-30：open(1) 剥 --args）——此处**无参数纯 URL 唤起**风险低，仍须真机验证（J-1）。
- 运行时降级：macOS < 14（Passwords.app 不存在）→ 就地提示「需要 macOS 14 或更高版本」，按钮禁用 + 说明（不做窗口级拦截，J-2）。

**权限撤销后的恢复流（D-18.3）**：

| 触发 | 检测 | 呈现 |
|---|---|---|
| bookmark 失效（`startAccessingSecurityScopedResource` 返回 false） | 每次授权目录访问前 / 监视循环内 | `DropzoneAuthStatusView` `.stale`：就地「放置区授权已失效」+「重新授权」→ 回 S0（失效不静默） |
| 目录被移动/改名/删除 | bookmark 仍指向旧路径 | 同上；附「该路径当前不可用」 |
| 用户主动撤销 | 设置页「导入」节「移除授权」（`.bordered` 次按钮） | bookmark 清除（D-18.4 单删 + 广播）、状态回 `.notAuthorized`、不静默；下次进向导回 S0 |

恢复语义：**授权可逆**。移除授权只删 bookmark（目录与文件不动），非破坏性；不弹确认——低风险可逆操作走就地反馈（D-1.3）。

**状态清单与转移表**：

| 状态 | 名称 | 进入条件 | 出口动作 | 关闭按钮 |
|---|---|---|---|---|
| S0 | 未授权 | bookmark 不存在/失效/被撤销 | 选目录成功→S1；失败→S0-E | 可用 |
| S0-E | 授权失败 | bookmark 写失败/面板异常 | 重试→S0 | 可用 |
| S1 | 等待新导出 | 已授权 | 检测到新文件（非已忽略指纹）→S2/S1.5；失效→S0-E | 可用 |
| S1.5 | 文件选择 | ≥2 新文件 或 含已导入过 | 选 1 个→S2；忽略→已忽略（S1） | 可用 |
| S2 | 预检中 | 选定文件 | 成功→S3；失败→S2-E | 可用 |
| S2-E | 预检失败（就地错误态） | precheck 抛错 | 重新预检→S2；**忽略→已忽略指纹**→S1 | 可用 |
| S3 | 预览去重 | 预检成功 | 导入→S4；返回→S1 | 可用 |
| S4 | 导入中 | 用户确认导入 | 成功→S5；失败→S5-E | **禁用** |
| S5 | 结果页 | 导入成功 | 完成/回等待→S1 | 可用 |
| S5-E | 导入失败 | 导入抛错 | 回等待→S1（all-or-nothing 零落库） | 可用 |

**贯穿态（任意态可达，S4 除外）**：

- **「关闭」= 放弃本次会话 + 停止监视**：bookmark 已持久（授权状态不丢），下次进入直达 S1 并补扫；**监视仅向导打开期间进行，关闭即停**（裁定⑤）。
- **锁定 = 监视停摆（fail-closed，裁定③）**：库锁定 → 停止检测与读取（数据面随 phase 拆除，D-10.3/D-6.1 类比）；解锁后恢复，进向导先补扫一次。

**窗口尺寸建议**：**640 × 600**（`config.windowWidth/Height` 模式；较既有 520–560 宽，容纳预览分类表 4 列信息密度）。头部「关闭」（BUG-6：Esc + 导入执行中禁用）+ Divider + 尺寸 + 预检失败 alert（本向导 Binding 传 nil 不触发）全部由壳提供；S0-S5 全在 content 闭包内自持。

### 4.3 负路径详解

**① 未授权 / 授权撤销** — S0/S0-E：见 §4.1。首次体验关键：S0 不得出现「打开密码 App」按钮（无目录可指向）；先授权再引导，顺序不可倒。

**② 放置区多文件 / 重复文件** — S1.5：
- 多文件：Passwords.app 导出默认文件名随系统语言本地化（中文环境实测为 `密码.csv`，2026-10-18 J-5 实样）；重复导出默认同名，系统弹**替换确认**，不自动改名为 `密码 2.csv`（2026-10-18 实样）→ 检测到 ≥2 个候选时**不自动猜**，列出（文件名 + 大小 + 修改时间 + 「已导入过」/「已忽略」徽标）让用户选。
- 「已导入过」判定：同名 + 同大小 + 同 mtime 与上次导入记录匹配（轻量指纹，UserDefaults）。已导入过但用户仍选 → 提示「此文件与上次导入一致，继续将全部作为新增」并放行（用户可能刻意重导）。
- 默认选中 = **最新修改时间**的那个（不勾选「已导入过」/「已忽略」的）。

**③ 坏格式 / 缺列 CSV** — **就地错误态 S2-E**（D-7.3；闭包内自持，`precheckError` Binding 传 nil 不触发壳 alert）：
- 呈现：`exclamationmark.triangle` 橙 40pt + headline「无法解析该文件」+ 错误摘要（ErrorPresenter 单源，D-12.3，不泄露行内容）+ 文件 pathLine + 双出口「重新预检」「忽略此文件（不再提示）」。错误 alert 只是补充，不得以弹窗代替就地态。
- **已忽略指纹**：点「忽略此文件（不再提示）」→ 落**已忽略指纹**（文件名 + 大小 + mtime，与「已导入过」指纹同机制、UserDefaults）；**该文件之后（同会话及跨会话）不再自动触发预检/选择**。S1 在监视区下展示「已忽略」区（含被忽略文件行 + [取消忽略] 恢复）；「取消忽略」清指纹，文件回到可被检测的行列。
- 缺列不直接失败——既有 precheck 对未识别列**降级并入备注不丢数据**（`ImportView.swift:145-147`）；坏格式仅指文件不可解析（非 UTF-8 / 零列 / 非 CSV）。

**④ 检测到文件但用户切走 / 向导留后台** — 监视生命周期（裁定⑤/D-7.5）：
- **呈现方式**：macOS sheet 不阻塞其他 App——用户点「打开 macOS 密码 App」切走后，**向导 sheet 保持打开、监视继续**；用户完成导出、切回 Coffer（App 激活回前台）时**补扫一次**，检测到即自动进预检（无需用户再点）。**覆盖范围**：向导打开期间 App 前/后台切换均覆盖；**向导关闭不监视、再次打开补扫**。
- 用户回到前台但文件未落盘（导出面板还开着）→ S1 保持，`DropzoneWatchStatusBadge` 下加一行 caption「还没看到新导出——请完成 Passwords.app 的保存」；不打断、不弹窗（D-7.5：被动检测不打扰）。
- **用户关闭向导 sheet**（中途放弃）→ **监视停止**；已导出文件不丢——下次打开向导先补扫，文件仍在放置区即被检出。关闭前无需警示（文件永不被 Coffer 删除，见 §4.6）。

**⑤ 导入中再来新文件** — S4 导入中**暂停监视入队**：新文件不打断当前导入；导入完成回 S1 后，排队的新文件作为下一候选进 S1.5。不做并发双导入（单事务串行）。

**⑥ 大文件** — 预检/导入慢：S2/S4 均带进度语义。S4 沿用 `ImportScaffold.importingBody`（ProgressView + 单事务文案逐字）；不承诺精确百分比（行数未知，进度条会假跳），文案明示「可能需要一点时间」。

**⑦ 空库 vs 有库去重预览** — S3：空库：去重无意义，预览**折叠为一行说明**「密码库为空，全部 N 条将作为新增导入」+ 统计，不展示分类表。有库：完整分类表（§4.4）。

**⑧ 锁定态（fail-closed，裁定③）** — 入口 `.disabled(phase != .unlocked)`（1001 门禁）；向导打开中库被锁定 → 监视停止、CSV 不读取（D-6.1/D-10.3），解锁后恢复 + 补扫；import_csv 的 1001 会话门禁兜底。

### 4.4 去重与预览

**匹配键与分类**：

- **匹配键**：`(Title, Username, URL)` 三元组**规范化后精确匹配**。URL 规范化：去协议（https://）、去尾部斜杠、host 小写（对齐现有 URL 处理心智）。
- **Password 不作为匹配键**：库内密码为密文，导入侧无法也不应明文比对；且以明文密码做匹配键本身是安全反模式（隐私论证经评审认可）。
- **已知限制（显式登记）**：本去重为**元数据级**——`(Title, Username, URL)` 一致但**密码已更新**的条目会被归「重复」默认跳过，不感知库内密码已陈旧。逃生口见下（可切「全部导入」新建不覆盖）。
- **分类**（每行归一类，互斥）：

| 分类 | 判定 | 默认动作 | 徽章（文本常显，颜色仅辅助，D-13.4） |
|---|---|---|---|
| 新增 | 库内无此三元组 | 导入 | 「新增」（蓝 `plus`） |
| 重复 | 三元组完全匹配（**含密码已更新的情形**） | **跳过**（安全默认：不覆盖） | 「重复」（灰 `checkmark.circle`） |
| 冲突 | Title 命中但 Username/URL 不一致 | 导入 + 行内「待确认」标记 | 「冲突」（橙 `questionmark.circle`） |

**预览信息密度（S3，对齐 D-8.4）**：

- **顶部**：文件来源（`pathLine` 中截断）+ 三档统计（**新增 N / 重复 M / 冲突 K**，复用 `ImportScaffold.statLabel` 三连，`ImportWizardShell.swift:190-208`）。
- **分类表**（ScrollView 内；复用 `ImportScaffold.failureList` 骨架 + 逐行 `DedupCategoryBadge`）：列 = 分类徽章 | 标题（lineLimit 1）| 用户名（lineLimit 1）| URL（`truncationMode(.middle)`，D-5.3）| 备注（冲突理由，caption2）。
- **批量切换（D-8.4）**：默认不逐行确认（N 可能上百），提供表头批量切换（「重复条目：跳过/全部导入」）+ 行内就地切换。反馈纪律：**即时统计反馈**（切换即时更新 statLabel 三连与「导入 N 条」按钮计数，N = 将导入行数）；**状态可见 + 可逆**（被改动的行保留显式徽章，可再切回，未入库无副作用）；**安全默认跳过**（不默认覆盖）；**VO**：徽章 label 含当前态 + 动作（如「重复，点按改为导入」，D-13.1/D-13.4）。
- **逃生口（元数据级去重限制的显式出路）**：「重复」区批量切换提示补「**若某条目密码已更新，可切换『全部导入』（新建不覆盖）**」——安全默认跳过的同时，给「库内密码已陈旧」用户显式出路。
- **底部动作**：`导入 N 条`（prominent，`.disabled(N == 0)`，P3 §6）+ `返回`（回 S1，不丢预览）。
- **文案**：冲突区附「不会覆盖库内已有条目；被跳过的条目可在导入后手动核对」（安全默认透明化）。

**冲突处理策略（⚠3 顺延登记）**：

- **仅「跳过」**：预览层剔除「重复」行 → 余行走**既有 `import_csv` 单事务**（对既有契约零改动）。
- **不做覆盖更新**：明文 CSV 覆盖库内密文是高风险面，未过 lead 裁定不做；不提供「覆盖」入口；「全部导入」= 新建不覆盖，非覆盖更新。
- **文件内重名**（同一 CSV 内 Title 重复）：沿用既有警告语义（`precheck.rs:144-151`「全部新建，不做去重」），在预览「冲突/备注」列提示，不拦截。

### 4.6 R2 安全纪律

| 纪律 | 规格 |
|---|---|
| **明文只进内存** | 放置区 CSV 读取→解析→比对，全部内存内完成；**不落副本、不写缓存、不写日志**（对齐既有 precheck/import 只读纪律，docs/07 §2.3）。解析后内存对象按行释放。 |
| **只提示不代办（D-6 硬纪律）** | 结果页删源警示（对齐既有 CSV 流 orange 警示 + ui-standard 三重保证措辞：本地读取/不落日志/零网络）；**绝不提供删除按钮**——删源一律用户经访达自行决定（`PuxImportView.swift:332-333` 先例）；Coffer 不因「监视该目录」而获删文件资格。 |
| **零网络** | 监视/检测为**本地目录读取**，不涉任何网络；措辞不得承诺「云端同步」类语义。 |
| **不落日志** | 文件名、目录路径、行数、用户名一律不进日志；错误文案经 ErrorPresenter 单源（D-12.3），不含明文值。 |
| **授权即同意 + 范围明示（D-18.1）** | 授权声明（只读/目标路径/用途/零网络/可撤销）**承载于同意界面本身**：S0 说明卡常显 + NSOpenPanel message 重申；选目录动作 = 同意监视，无静默获取、无二次确认；授权只读、可撤销。 |
| **授权可撤销（D-18.3/D-18.4）** | 设置页「导入」节 + 向导内均可达「移除授权」（非破坏性，D-1.3 就地反馈）；单写单删；失效不静默。 |
| **凭证不比对** | 去重匹配键**不含密码明文**；库内密文不参与比对，杜绝「明文导入侧触碰密文」的泄露面。 |
| **不自动覆盖** | 冲突默认跳过，覆盖能力不引入（⚠3 顺延）；「全部导入」= 新建不覆盖。 |
| **锁定态 fail-closed** | 库锁定 → 监视停摆、不读取 CSV（裁定③，D-6.1/D-10.3）；解锁后恢复 + 补扫。 |
| **已忽略指纹** | 忽略 = 元数据指纹（文件名+大小+mtime）落 UserDefaults，**不含明文、不含内容摘要**；取消忽略可清。 |
