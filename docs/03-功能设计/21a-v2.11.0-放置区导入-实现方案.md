## 0. 结论速览

- **P-4 裁定：去重分类在 core 完成**（cf-importer 新增 `analyze_dropzone`），Swift 只消费分类结果与非敏感行元数据（title/username/url + category）。决定性理由：**密码明文全程不跨 FFI**（最强的 R2 姿态）——CSV 的明文（含密码）只在 core 内存内被解析与分类，Swift 侧仅见非敏感元数据；而 Swift 侧 `FfiItemSummary` 只有 title（`cf_ffi.swift:5161` 实证，无 username/url），Swift 侧匹配需逐条详情 N+1 FFI 且把去重逻辑放进无单测设施的一侧。
- **目录监视机制裁定：DispatchSource（vnode）+ 关键转换点补扫兜底**，不引入 FSEventStream、不做纯轮询。
- **bookmark 服务**：新建 `macos/Coffer/Dropzone/` 目录三文件（bookmark 存取 / 目录监视 / 指纹存储），`macos/` 当前零 security-scoped bookmark 代码（grep 实证），全部新建。
- **entitlement 零改动**：现 `com.apple.security.files.user-selected.read-write`（`macos/Coffer/Coffer.entitlements` 已有）即为 security-scoped bookmark 的充分前置，无需新增 entitlement。「只读」为**代码纪律级承诺**而非 entitlement 边界——诚实边界见 §5.4。
- **并行分组**：两独立泳道（core 链 / Swift 服务与 UI 链）+ 一条主关键路径 `G1 → G2 → G4 → G6`。ImportWizardShell.swift 零改动保住 C-4 四格式回归面归零。
- **不可逆决策**：新增 FFI 类型与方法（`precheck_dropzone` / `import_dropzone`）与 UserDefaults 键名 = 持久契约，标「待 lead 确认」后方可冻结（§6）。

## 1. P-4 裁定：去重匹配判定落点

### 1.1 结论

**core（cf-importer）侧计算分类**。具体：

- 新增 `cf_importer::dropzone` 模块：
  - `analyze_dropzone(path, store) -> DropzoneAnalysis`：解析 CSV（复用 `parser::parse_csv` + `mapping::map_row` 同管线）+ 读 store 既有三元组 + 逐行分类。
  - `import_dropzone(path, include_line_nos, store) -> CsvImportResult`：重解析（确定性同管线）→ 按行号过滤 → 走既有 `import_models` 单事务写入（all-or-nothing 逐字保留）。
- 新增 FFI：`VaultSession.precheckDropzone(path:)`（只读，1001 门禁）、`importDropzone(path:includeLineNos:)`（1001 门禁），经 cf-session 薄委托（镜像 `vault.rs:888-892` import_csv 模式）。
- **`precheck_csv` / `import_csv` 既有函数体零改动**——只新增，不改动，C-4 四格式回归面归零。

### 1.2 依据（四维度）

| 维度 | core 侧 | Swift 侧 | 裁决 |
|---|---|---|---|
| **契约影响面** | store 内已有全量访问（`repos.items.list` / `repos.fields.read_fields_for_item` / `repos.urls.read_for_item`，`cf-store/src/repo/*.rs` 实证）；新 FFI 面 = 一个报告类型 + 一个导入方法 | `FfiItemSummary` 只有 title（`cf_ffi.swift:5161-5214` 实证）——Swift 侧需逐条 `item_details` N+1 FFI（每次解密）或扩 FfiItemSummary 字段（同样是 FFI 改动） | **core** |
| **R2 面（决定性）** | 明文（含密码）在解析→分类→导入全在 core 内存内完成，**密码不跨 FFI**；Swift 只见非敏感行元数据 | 若 Swift 侧匹配，要么密码随 `ImportModel` 跨桥（`mapping.rs:102` password 字段），要么先过滤再导入——R2 姿态弱 | **core** |
| **性能** | 百条级库：构建既有三元组 `HashMap` O(N)（每条目 ~2 次 SQL 读，N≈数百可忽略） | Swift 侧 N 次 FFI 详情调用，每次跨桥解密 | **core** |
| **测试性** | Rust 单测直接覆盖分类纯逻辑（in-memory `ItemStore` 先例 `cf-importer/src/lib.rs:365-396`） | Swift 侧无同等级单测设施 | **core** |

**一致性（所见即所得）**：预检与导入复用同一条解析管线（确定性），行号映射在 core 内部一致；「报告所见 = 导入所得」契约与既有 CSV 面同构（`lib.rs:149-152` 注释）。

### 1.3 备选对比

| 方案 | 契约面 | R2 姿态 | 性能 | 测试 | 结论 |
|---|---|---|---|---|---|
| **A. core 扩展报告字段（采纳）** | 新 FFI 报告类型（`FfiDropzonePrecheck`）；既有类型不动 | 最强：密码不跨 FFI | O(N) 内存集合 | Rust 单测 | ✅ |
| B. Swift 侧读库比对 | 需扩 FfiItemSummary 或 N+1 详情 | 弱：密码跨桥风险 | N 次 FFI | 无单测设施 | ❌ |
| C. core 返回全部 ImportModel 给 Swift 由 UI 匹配 | 明文跨 FFI（含密码） | **违规**（R2） | — | — | ❌ 否决 |

### 1.4 新 FFI 契约面（只增不改）

```
// core/cf-importer/src/dropzone.rs（新增）
enum DedupCategory { New, Duplicate, Conflict }

struct DropzoneRow {
    line_no: u32,            // 文件行号（1 起，表头=第1行）——导入选择集身份
    title: String,           // 非敏感元数据（明文仅进 core 内存）
    username: Option<String>,
    url: Option<String>,
    category: DedupCategory,
    conflict_note: Option<String>,   // 冲突理由（「与库内条目用户名不同」等，caption2）
}

struct DropzoneAnalysis {
    rows: Vec<DropzoneRow>,          // 顺序 = 文件行序（仅非空行）
    total_rows: u32,                 // 数据行总数（含全空行）
    valid_rows: u32,                 // 非空行数（= rows.len()）
    new_count: u32, duplicate_count: u32, conflict_count: u32,
    warnings: Vec<String>,           // 复用既有警告语义（含文件内重名）
    unmapped_columns: Vec<String>,
}

pub fn analyze_dropzone(path: &Path, store: &ItemStore) -> Result<DropzoneAnalysis, CfError>;
pub fn import_dropzone(path: &Path, include_line_nos: &[u32], store: &mut ItemStore)
    -> Result<CsvImportResult, CfError>;
```

- `include_line_nos` 语义：仅「将导入行」的文件行号集合。UI 在 S3 预览上做批量/逐行切换后，把最终 include 集传给导入（对应按钮「导入 N 条」）。**导入不需要再分类**——`write_model` 恒新建（`lib.rs:181-290`，无覆盖语义），分类只决定「哪些行进导入集」。
- 文件在预检与导入之间被改动的竞态：导入时重解析，若任一 include 行号在重解析后的非空行集合中缺失 → 返回 `CfError::ImportFailed`（就地错误 → 回 S1 重新预检）。fail-closed on drift，零额外数据。
- 去重匹配键规范化：`(Title, Username, URL)` 三元组精确匹配；URL 规范化 = 去协议 / 去路径 / 去尾部斜杠 / host 小写（对齐 `cf-audit/src/audit_rules.rs:470 url_host` 的 host 抽取心智，新写 `normalize_dedup_url` 于 dropzone 模块内，`provisional` 直至 J-5 实样核对）。Password 不作为匹配键（设计已裁，防安全反模式）。

### 2.2 目录监视机制裁定

| 方案 | 复杂度 | 可靠性 | 资源 | 结论 |
|---|---|---|---|---|
| **A. DispatchSource.vnode（`.write/.delete/.rename`）+ 补扫（采纳）** | 低（一目录一 `O_EVTONLY` fd） | 中：事件可能合并/丢失，**由关键转换点补扫确定性兜底** | 1 fd | ✅ |
| B. FSEventStream（CoreServices） | 中高（run loop 调度 + 回调） | 高（系统级合并去抖） | 每流较多 | ❌ 过重（短生命周期单目录） |
| C. 定时轮询 Timer | 最低 | 中（延迟=间隔） | 无 fd | ❌ 浪费且有延迟 |

**理由**：监视仅向导打开期间（裁定⑤，短生命周期、单目录），DispatchSource 最轻；其事件丢失/合并缺陷由**补扫**确定性覆盖——补扫时机 = ①监视启动（S1 进入）②App 回前台（`applicationDidBecomeActive`，W-5 主场景：用户切去 Passwords.app 导出后切回）③解锁恢复。这三个时机正是设计 W-1/W-5 的既有要求，不构成新增成本。**不做后台常驻监视**（裁定⑤）。

**监视生命周期（与 fail-closed 结构绑定）**：向导 sheet 挂在 `MainView` 下，`MainView` 仅 `.unlocked` 渲染（`RootView.swift:50-52` 实证）→ 锁定相变即拆树、sheet 随拆、监视自动停——结构性 fail-closed（W-2）。向导内再加 `onChange(of: model.phase)` 防御性停表 + `onDisappear` 停表（防「关闭按钮之外的路径」泄漏 fd）。

### 2.3 指纹存储契约（UserDefaults 键名，**待 lead 确认后冻结**）

对齐既有 `clipboardClearSecs` / `autoLockMinutes` 轻量持久化先例（`AppModel.swift` didSet + UserDefaults）：

| 键 | 类型 | 语义 | 写点 |
|---|---|---|---|
| `dropzone.bookmark.data` | `Data` | security-scoped bookmark（URL.withSecurityScope） | 唯一写点=向导 S0 授权 |
| `dropzone.imported.fingerprints` | `Set<String>` | 已导入过指纹，键=`<文件名>\u{1F}|<size>|<mtimeMs>` | S5 导入成功 |
| `dropzone.ignored.fingerprints` | `Set<String>` | 已忽略指纹，键同左 | S2-E / S1.5 忽略 |

指纹只含元数据（名+大小+mtime），**不含明文、不含内容摘要**（S-4 判据；与设计 §4.6 一致）。「已导入过」判定 = 指纹命中 → S1.5 徽标 + 提示「与上次导入一致，继续将全部作为新增」放行（用户可刻意重导）。

## 3. 接口签名草案

### 3.1 向导与 AppModel 接线（showImportDropzone）

```swift
// AppModel.swift（新增，G5）
@Published var showImportDropzone = false            // 三处入口同源触发
@Published var dropzoneBookmark: DropzoneBookmark?   // 授权目录；nil = 未授权。D-18.4 广播单源
```

### 3.2 bookmark 生命周期 API（D-18.4 单写单删 + 广播）

```swift
// DropzoneBookmarkStore.swift（G3）
struct DropzoneBookmark: Equatable {
    let url: URL            // 授权目录 URL（安全作用域）
    let bookmarkData: Data  // 持久化凭据
}
enum DropzoneAuthStatus { case notAuthorized, authorized(DropzoneBookmark), stale(DropzoneBookmark) }

final class DropzoneBookmarkStore {
    static let shared: DropzoneBookmarkStore     // 或经 AppModel 注入
    func load() -> DropzoneBookmark?                    // 读（UserDefaults §2.3 键）
    func save(_ url: URL) throws -> DropzoneBookmark    // ★ 唯一写点（向导 S0）
    func remove()                                       // ★ 唯一删点（设置页「移除授权」）
    func validate(_ b: DropzoneBookmark) -> Bool        // 失效检测（A-3，见 §5.1）
    func withAccess<T>(_ b: DropzoneBookmark, _ body: () throws -> T) throws -> T
        // startAccessingSecurityScopedResource 配对（A-4：用完停止、不驻留句柄）
}
```

- **单写单删**：写=向导 S0（`save` 单点）；删=设置页「移除授权」（`remove` 单点）。广播 = `AppModel.dropzoneBookmark` 为单一真相，删除置 nil → 向导（打开中）与设置页同源同步回 `.notAuthorized`（D-18.4）。
- `withAccess` 内部 `guard startAccessing... else throw stale` → defer stop；`validate` 供 S0/S1 与监视循环内失效检测（D-18.3 失效非静默）。

### 3.3 监视回调

```swift
// DropzoneDirectoryWatcher.swift（G3）
final class DropzoneDirectoryWatcher {
    func start(watching url: URL, onEvent: @escaping () -> Void) throws   // DispatchSource.vnode
```

### 3.4 去重分类数据流（P-4 core 面）

```
Swift（DropzoneImportView S2）──path──▶ session.precheckDropzone(path:)      [core: 解析+读库+分类]
        ◀── FfiDropzonePrecheck（rows[] + 三档计数）──（仅非敏感元数据，密码不跨桥）

        ◀── FfiCsvImportResult{importedRows} ──▶ S5 结果页 / model.reloadItems()
```

## 5. 风险与开放点

### 5.1 bookmark 失效语义实证计划（A-3）

设计 D-18.3 要求失效非静默，但失效触发边界（目录删除/改名/权限变更/系统重启后）的**精确语义**由 dev-team 实证（docs/21 §8 诚实边界）。实证计划（G4/G6 集成前、Wave 4 内做）：

1. 写一临时目录 bookmark → `validate()` true（基线）；
2. `rmdir` 目录 → `validate()` 必须 false → `.stale` + 重新授权路径（不崩溃不静默，A-3）；
3. `mv` 改名 → 同上（bookmark 仍指向旧路径）；
4. `chmod 000` → 记录 `startAccessingSecurityScopedResource` 实际返回值（可能 true 但 read 失败——捕获 `CFRead`/目录枚举错误并入 stale 判定）；
5. **重启后持久性**：bookmark 落 UserDefaults，验证重启后 `load()` 非空且目录仍可访问（security-scoped bookmark 跨重启语义，需一次真机验证）；
6. 失效判定落点：`validate()` + 每次 `rescan()` 目录枚举异常 → 统一转 `.stale`（就地呈现 + 重新授权，D-18.3）。

### 5.2 BUG-30 类沙盒 open 坑（J-1）

`NSWorkspace.shared.open(/System/Applications/Passwords.app)` 为**无参数纯 URL** 唤起（设计已排除 --args 传递场景）——BUG-30 是 `open(1)` 剥 `--args` 致 helper argv 空，本路径无参数、低风险，仍须真机验证（J-1 判据保持）。macOS < 14 降级：检查 Passwords.app 是否存在（`FileManager.default.fileExists`），不存在 → 就地提示 + 按钮禁用 + 说明（J-2），不做窗口级拦截。

### 5.3 四格式回归门禁（C-4）验证口径

C-4 = CSV/1PUX/Bitwarden/OPVault 导入行为与重构前逐项等价。**本方案对既有导入面零改动**（只新增 FFI 方法 + 新视图，`precheck_csv`/`import_csv` 函数体、四格式向导、`ImportWizardShell.swift` 均不动），故 C-4 退化为「现有全量门禁绿 + 四格式 SmokeTest 路径仍过」。验证口径：

1. `cargo test` 全量（workspace 门禁，含 cf-importer 既有用例——尤其 CSV 故障注入 `lib.rs:400-433`）；
2. swiftc 构建绿 + `macos/Coffer/SmokeTest` 冒烟过（绑定重生成后 Swift 链路验证）；
3. 四格式导入向导**手工回归**各走一遍选文件→预检→导入（或既有 P3 自动化用例）；
4. grep 断言：`ImportWizardShell.swift` 无 diff（`git diff --stat` 该文件为空）。

### 5.4 诚实边界

- **「只读」是代码纪律级承诺，非 entitlement 边界**：现 `com.apple.security.files.user-selected.read-write` 为既有 CSV 导入所需，security-scoped bookmark 的访问粒度由该 entitlement 决定（read-write 是 read-only 的超集，无法并存两个键）。放置区「只读」由代码纪律保证：grep 断言无写目录路径、D-6 无删除按钮、目录永不被 Coffer 修改。授权声明文案（S0）须如实，不宣称 entitlement 级只读。
- **指纹 mtime 粒度**：同名同大小同 mtime 秒级误判「已导入过」为良性（仅徽标 + 可覆盖提示，非拦截）；不做内容摘要（S-4 禁）。
- **文件预检→导入竞态**：以「重解析 + 行号子集校验」fail-closed（§1.4），可选加文件尺寸+mtime 校验（非必需）。
- **J-5 发版门禁（2026-10-18 已核销）**：实样核对结果——列头 `Title,URL,Username,Password,Notes,OTPAuth` 逐字一致；菜单名实测「将所有密码导出至文件…」；默认文件名实测 `密码.csv`（本地化，非 `Passwords.csv`）；重复导出弹替换确认（非 `密码 2.csv`）。列映射 P-2 正式化；生产代码无文件名依赖。本门禁关闭，v2.11.0 可发版。
