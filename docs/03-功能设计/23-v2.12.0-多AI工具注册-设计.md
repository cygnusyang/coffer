## 1. 结论先行

### 1.1 改什么

1. **设置页「MCP / Agent 协作」节内新增 AI 工具维度的多目标注册面**：单一「Claude Code 注册」行被替换为工具列表，每行独立开关、独立状态、独立复制入口。
2. **总开关语义扩展为「允许 + 批量」**：OFF→ON 为所有已安装工具批量注册；ON→OFF 为所有已注册工具批量移除（有注册项时先确认）。
3. **每工具开关成为实际授权单位**：总开关是前提，工具开关是决策；新出现的工具默认 OFF（安全默认，见 §4.2）。
4. **复制入口下沉到行**：coffer 数据源下移除全局「复制注册命令」行，改由每个工具行提供「复制命令」；原因是单条命令在多工具下失去唯一目标。
5. **概念词分治**：「数据源」仅指 1Password CLI / Coffer 自家库；「AI 工具」指被登记的 MCP 客户端。二者不互换、不互相修饰。

### 1.2 不改什么

1. **MCP 服务器进程边界**：主 App 不宿主服务器，不 spawn `coffer`（docs/06 §6.2）。
2. **注册值与解锁链**：注册项只含 `COFFER_VAULT_DIR` + 包内 `coffer` 路径，无密码 env；解锁一律走 MCP 解锁托管。
3. **MCP 解锁托管节**（`McpEscrowSettingsSection`）：三态、主密码确认、二次确认、文案全部保持。
4. **1Password CLI 数据源分支**：不显示 AI 工具列表，保留现有单行「复制注册命令」形态（无托管即无免密解锁，自动注册无意义）。
5. **「查看使用记录」禁用占位行**与节 footer 结构：保留，仅 footer 文案补多工具措辞。
6. **DESIGN.md 条款**：除 **D-7.2a（节内嵌空态，图标 40→24pt）** 与 **D-5.5（可照抄技术串，命令块不截断）** 两处**已登记例外**外，其余均为既有条款的应用；另有 D-11.8（名称 `lineLimit(2)`，D-5.1 的局部例外）与 D-13.6（`.help` 不作 a11y 兜底）已登记。**新增例外须先在 DESIGN.md §16 登记，再在本文件引用**，不得就地放宽。

## 3. 概念模型

### 3.1 两个正交维度

| 维度 | 取值 | 回答的问题 | 事实落点 | UI 位置 |
| --- | --- | --- | --- | --- |
| **数据源（provider）** | 1Password CLI、Coffer 自家库 | MCP 服务器从**哪里取密** | `coffer mcp --provider <值>` | 「数据源」行（下拉） |
| **AI 工具（target）** | Claude Code、CodeBuddy、Codex（+ copy-only 5 家） | **谁**被登记为 MCP 客户端 | 各工具自己的配置文件 | 「AI 工具」列表 |

术语纪律（判定方式：逐句核对文案表与代码类型名）：

| 规则 | 说明 |
| --- | --- |
| provider 一词**只**用于数据源 | 不得出现「Claude Code 数据源」「数据源 = Codex」等表述 |
| target 的中文一律写「AI 工具」 | 「客户端」「集成」「provider」均不得用于本维度 |
| 代码类型建议名 `McpTarget` | 不复用 `McpProvider`；不复用 `McpRegistrationState` 承载 provider |
| 用户可见文案不出现英文 target | 只写工具官方名 |

### 3.2 状态归属（一对一）

- 注册态**逐个 target 持有**；一个 target 至多一条注册项（服务器名恒为 `coffer`，重注册即覆盖 = upsert）。
- 由于注册值内含 `COFFER_VAULT_DIR`，单个 target 的注册态实际是三元判定：**未注册 / 已注册（目录 = 当前库）/ 已注册（目录 ≠ 当前库）**。三者是三个独立渲染态，不是「已注册 + 附注」。
- **跨 target 无共享状态**：一个 target 失败不影响另一个 target 的结果、文案、开关。
- **总开关是唯一跨 target 的聚合控制**，但其状态不蕴含任一 target 的事实（总开关 ON ≠ 全部已注册）。UI 不得用总开关颜色暗示工具就绪度。

### 4.2 总开关与每工具开关的从属关系

| 总开关 | 工具开关 | 语义结果 |
| --- | --- | --- |
| OFF | 不可拨（禁用） | 事实为 `notRegistered` 时显示「未启用」+ 行内 hint；存在残留 / 失败等事实态时**照常渲染事实**（§5.6、REV-01），不得一律写成「无注册项」 |
| ON → OFF（切换瞬间） | 全部强制 OFF | 批量移除；有注册项时先确认；失败行落 `cleanupNeeded` |
| OFF → ON（切换瞬间） | 已安装且未注册者自动置 ON | 批量 upsert（含 `registeredElsewhere` → 更新为当前库） |
| ON（稳定态） | ON | 保持注册；若检测到注册项缺失则重新注册 |
| ON（稳定态） | OFF | 不注册；若存在注册项则移除该 target |
| ON（稳定态，新出现的工具） | **默认 OFF** | 不自动授权。安全默认：新安装的 AI 工具不得静默获得取密能力，需用户显式打开 |

- 「总开关 ON 即全部工具可用」是**错误读法**：总开关只打开通道，实际授权逐工具成立。此点在总开关 caption 中明示（C-02）。
- **OFF ≠ 无注册项（REV-01）**：总开关 OFF 只把 `notRegistered` 渲染为「未启用」态；`cleanupNeeded` / `failed` / `registered` / `registeredElsewhere` / `registering` / `removing` 一律**按事实渲染**。批量移除失败后总开关已 OFF 而注册项仍在，此时必须保留「需清理」+「再次清理」+ C-13 横幅，**仅开关禁用**——否则用户看不到残留、也没有清理入口，而该工具此刻仍能读库。
- **关闭确认清单（REV-04）** = 所有**可能已写入**的目标：`registered` / `registeredElsewhere` / `cleanupNeeded` / `failed`（注册失败可能已部分写入）。在飞 `registering` 视为可能写入：确认后**取消在飞任务**并转 `cleanupNeeded`，交给移除队列收尾。
- **批量 ON 跳过的目标（REV-18）**：只对 `notRegistered` / `registeredElsewhere` 发起 upsert；`versionUnsupported` / `notInstalled` / `checkFailed` 不参与批量，避免对不可用或状态未知的目标反复失败。
- **开关初值（REV-03）**：开关意图**仅存活于页面会话**；重进页面 / 重开设置窗时初值 = 事实——`registered` / `registeredElsewhere` → ON，`notRegistered` / `cleanupNeeded` → OFF，`failed` → OFF（事实优先）。R-4「失败不回弹」只在**同一会话内**成立，跨会话以事实为准。

### 5.3 空态：无任何已安装的自动注册工具

│  AI 工具                                        ⟳      │

│      ◌                                                 │
│      未检测到 AI 工具                                   │
│      安装 Claude Code、CodeBuddy 或 Codex 后重新检测，   │

### 5.4 关闭总开关的确认

仅在存在**可能已有注册项**的行时出现：`registered` / `registeredElsewhere` / `cleanupNeeded` / `failed`（注册可能已部分写入，或该工具侧仍有旧项） / `registering`（在飞）。`notRegistered` 与 `notInstalled` 不计入（无残留）：

```text
  ┌ 关闭「启用 MCP 服务器」？ ─────────────────────────┐
  │  将从以下工具移除 coffer 注册项：                  │
  │    · Claude Code                                   │
  │    · CodeBuddy                                     │
  │  移除后这些工具不再能经 MCP 访问本机密码库。        │
  │  MCP 解锁托管保持开启，不受影响。                   │
  │                                                    │
  │                 [ 取消 ]  [ 关闭并移除注册 ]        │
  └────────────────────────────────────────────────────┘
```

- 无任何可能已写入的目标时**不弹确认**，总开关直接落 OFF（无可破坏对象即无确认负担）。
- 确认清单只列可能残留的目标；`notRegistered` / `notInstalled` / `versionUnsupported` 不进清单。
- `failed` 行进清单的理由：注册命令可能已写入配置后才失败（如写入后 confirm 读回失败），不清理即留下用户不想要的注册项。
- **确认后对 `failed` / `registering` 行补一次 best-effort remove**：先取消在飞任务，再按目标逐个尝试移除；移除成功落「未注册 · 已移除」，失败落 `cleanupNeeded`。文案不承诺「已全部清除」，而是「已尝试移除，残留见各行状态」。
- 确认按钮为 destructive；取消为默认按钮（Return 不触发移除）。
- **清单正文 ≤5 行**（破坏面句 + 最多 3 个工具名 + 不连带句）；目标 >3 个时写「前 3 个」+「等 N 个」，alert 内不做滚动。
- 关闭总开关**不**关闭 MCP 解锁托管（两个开关各自独立，文案明示）。

### 5.5 失败与批量部分失败

```text
│  ⚠ 已移除 2 个工具，1 个需手动清理                      │
│                                                        │
│  ○ Claude Code    未启用（已移除注册项）   [ ⊘  ]      │
│  ○ Codex          未启用（已移除注册项）   [ ⊘  ]      │
│  ⚠ CodeBuddy      已停用，但注册项未清理   [ ⊘  ]      │
│                   在终端运行 codebuddy mcp remove      │
│                   coffer · 再次清理                     │
```

- 图中 `○` 行是 `notRegistered + OFF` 的「已移除」变体：与可拨的 `notRegistered` 行**同符号**（ui-standard 定：事实同为无注册项，符号随母态），靠**开关禁用 + 次文案「已移除注册项」**区分；不得改画成 `minus.circle`（r0.8 统一）。
- OFF 下只有两种渲染面（详见 §5.6）：`notRegistered + OFF` → **未启用**（「刚移除完」只改次文案，不另立状态）；`cleanupNeeded + OFF` → **已停用，但注册项未清理**。二者必须在关闭态如实渲染，且残留行的「再次清理」保持可用（REV-13 / REV-01）。
- 聚合提示为**节内就地横幅**（非 alert，D-1.3 / D-7.3），一次批量一行，不逐行弹窗（D-8.2）。
- 批量不中断：任一 target 失败后继续处理其余 target（D-8.1）。

### 5.6 「总开关 OFF + 残留」组合（REV-01）

批量移除后总开关已 OFF、但个别注册项没清掉时的呈现在此处；这是 REV-01 的 CRITICAL 场景，图为唯一口径：
```text
│  ⚠ 已移除 2 个工具，1 个需手动清理                      │
│                                                        │
│  启用 MCP 服务器                           [ ⊘ 关闭 ]  │
│                                                        │
│  ⚠ CodeBuddy      已停用，但注册项未清理   [ ⊘  ]      │
│                   在终端运行 codebuddy mcp remove      │
│                   coffer · 再次清理 · 复制清理命令      │
│  ○ Claude Code    未启用（已移除注册项）   [ ⊘  ]      │
│  ○ Codex          未启用（已移除注册项）   [ ⊘  ]      │
```

- **事实态优先**：残留行按 `cleanupNeeded` 渲染（主文案「已停用，但注册项未清理」+ 命令块 + 「再次清理」），**不得**降级为「未启用 / 先打开总开关」。
- **仅开关禁用**：`cleanupNeeded` 的「再次清理」与「复制清理命令」在总开关 OFF 时**仍可用**——清理动作不依赖授权链，允许用户在关闭状态下收尾。
- **C-13 横幅常驻**到该行清零；横幅与行内状态同源（同一计数），不得只留其一。
- 其余已清理行显示「未启用」（`notRegistered` + OFF 变体），与残留行同屏共存。

### 6.2 意图与实际的一致性

| 规则 | 说明 |
| --- | --- |
| 开关 = 用户意图；行状态 = 事实 | 二者分离呈现，不用开关位置冒充注册结果 |
| 失败**不回弹**开关 | 注册失败后开关保持 ON，行显示失败 + 重试（回弹会让用户以为未操作过） |
| 前置不满足时**不产生意图** | 未安装 / 版本不支持 / 总开关 OFF / 辅助程序缺失 → 开关禁用，不记录 ON |
| `cleanupNeeded` 开关为 OFF | 用户意图是停用，残留是事实；不得显示 ON |
| 反向即取消 | 排队中或注册中拨回 OFF → 取消排队 / 取消在飞任务并尝试移除 |
| **意图只活在会话内（REV-03）** | 重进页面 / 重开设置窗时，开关初值 = 事实派生：`registered` / `registeredElsewhere` → ON；`notRegistered` / `cleanupNeeded` / `failed` → OFF。会话内「失败不回弹」不跨会话继承 |
| 事实态不受总开关约束（REV-01） | 总开关 OFF 时，`cleanupNeeded` / `failed` 等事实态照常渲染自身文案与可救动作（`failed` 的「重试注册」除外，需总开关 ON） |
| **开关初值 = 事实派生**（REV-03） | 每次进入页面（含关窗重进、解锁重开）开关初值由该行事实决定：`registered` / `registeredElsewhere` / `registering` → ON；`notRegistered` / `cleanupNeeded` / `failed` → OFF。**意图只在页面会话内成立**，不跨会话持久化——所以「失败不回弹」只在本次会话内成立，重进后以事实为准（失败过的行回 OFF，因为事实是无有效注册项）。这样避免「上次想开」被当成「现在已开」 |

### 6.3 状态迁移（事件 → 迁移）

| 起点 | 事件 | 终点 | 备注 |

**9.5.1 行结构**（主组与折叠组同构，唯一行形态；480pt 窗内不换布局）

| 槽位 | 规格 | 既有出处 |
| --- | --- | --- |
| 图标槽 | 槽宽 = **基准 16pt**（= 当前 callout 线盒宽），随 Dynamic Type 同步放大，左对齐；**锚定首行 line box 中线（非文本块中线）**。`McpSettingsView` 的 `.frame(width: 16)` 仅作出处证据，**不作实现形态**（D-11.4：不得写成固定 frame） | `McpSettingsView` statusRow / registrationRow `.frame(width: 16)` |
| 槽–文字 | 8pt | 同上 `HStack(spacing: 8)` |
| 文本块 | `VStack(alignment: .leading, spacing: 2)` | 同上 |
| L1 工具名 | `.body` + `.primary`（与「启用 MCP 服务器」标签同层） | Form 默认字号 |
| L2 状态词 | 首行内跟 L1，间距 8pt，`.body` + `.secondary`；**锚定首行基线**（`alignment: .firstTextBaseline`）；**不截断**（不设 `lineLimit`，`.fixedSize(horizontal: true, vertical: false)` 取固有宽 + `.layoutPriority(1)`） | 与线框「名称  状态」同排；REV-14 / D-11.8 |
| L3 次文案 | 次行，`.callout` + `.secondary`，缩进自动 = 16+8 = 24pt（VStack 自然对齐，**不加 padding**） | statusRow 次文案 `.callout` |
| 行高 | 单行态 ≥32pt / 双行态 ≥44pt，点击区不小于 24pt | docs/22 §2 可访问性 |
| 尾部列 | 距文本块 12pt，右对齐；内容按态取「开关」或「动作组」 | 8/12/16 既有节奏 |

- **L1 从 `.headline` 降为 `.body`**（偏离既有单行注册行）：单行变多行列表后，3 条 headline 会与 Section header 抢层级；「名称 · 状态」同字号共读一句，与 §5.1 线框一致。
- **争宽优先级（D-11.8，D-5.1 的局部例外）**：空间不足时**先截 L1 工具名**（`lineLimit(2)` + `.truncationMode(.tail)`；默认字号通常 1 行，大字号可至 2 行），**L2 状态词不截断**。数字依据：480pt 窗首行文本区 ≈366pt，最长状态词「已注册到其他库」≈91pt（占 25%），名称余量可容 ≈20 汉字（真实最长 8 字符）。名称被截断时**全名经行级 AX label 与 `.help(全名)` 双通道可达**；`.help` 不作 a11y 兜底（D-13.6）。

- **截断优先级（REV-14）**：**L2 状态词不截断**（不设 `lineLimit`，加 `.layoutPriority(1)`；状态词是状态判别本身，最长 7 字 ≈ 91pt）；空间不足时**先截 L1 工具名**（`lineLimit(2)` + `.truncationMode(.tail)` + `.help(全名)`）；大字号下 L1 两行仍不够则由 `.help` 兜底，L2 始终完整。名称与状态同排时，名称占弹性宽、状态取固有宽（`.fixedSize(horizontal: true, vertical: false)`）。

**9.5.3 语义色映射**

- 三档色阶（按「下一步动作落在哪里」分桶，r0.9 重写）：**green** = 终态达成（仅 `registered`）；**orange** = 需**就地**处理、本页即可完成（`failed` 重试注册 / `cleanupNeeded` 再次清理 / `registeredElsewhere` 更新为当前库）；**secondary** = 中性 / 进行中 / 不适用 / **需离开本 App 才能完成**（安装 → `notInstalled`、升级 → `versionUnsupported`）/ **状态未知须先重检**（`checkFailed`）。依据：原「orange = 需要你动手」过粗——「动手」分页内页外；若安装 / 升级也上橙，折叠组 8 行（3 家未安装 + 5 家 copy-only）会成一片橙，噪音压过真正可就地修复的故障。
- **不上 red**：red 在本仓保留给库 / 加密级破坏性失败；注册失败是可修复的本地配置问题。
- **只上图标，不上文字**：① D-13.4 已由图标 + 主文案双通道承担；② 480pt 双行块内彩色文字在深色模式过饱和；③ 既有 statusRow / registrationRow 均只给图标槽上色。

**9.5.4 开关与动作控件**

- **开关**：`.toggleStyle(.switch)` 系统默认尺寸，**不收小号**——工具开关与总开关同属一条授权链。
- **行内动作**：一律 `.buttonStyle(.borderless)` + `.controlSize(.small)`，同次最多 2 个，`·` 分隔 8pt。主救动作（重试注册 / 更新为当前库 / 再次清理）用 `.tint(.accentColor)`；辅助动作（复制命令 / 复制清理命令）用 `.secondary`。
- **复制反馈**：标签就地换「已复制」+ `checkmark`，**1.5s** 复位（lead 裁定统一 D-1.2，不设 2s 例外），不弹 alert、不改行高。
- **行尾 Menu：本节不引入**。收纳阈值 = 单行需 ≥3 个动作，或出现「打开配置文件位置」这类非主路径动作。

**9.5.5 深色 / 窄宽 / 大字号**

- 全部色值为系统动态语义色，深色自动重映射，无 hex、无固定 RGB。
- 次要文字只用 `.secondary`，**不用 `.tertiary`**；`.tertiary` 仅保留给空值占位 `—`。
- **路径**：`.font(.system(.caption, design: .monospaced))` + `.secondary` + `.lineLimit(1)` + `.truncationMode(.middle)` + `.textSelection(.enabled)` + `.help(完整路径)`。registeredElsewhere 次文案拆两行：第 1 行短句，第 2 行单独路径。
- **`.help` 属悬停通道，不构成可访问性兜底**：失败行的 AX 可访问性文本必须是**未截断的完整主文案**（行级 `.accessibilityLabel` 含完整失败原因），3 行截断只作用于视觉层、不作用于 AX 层——否则键盘与 VoiceOver 用户看到的仍是被截断的唯一信息（与 §9.1「次文案并入行 label」同一纪律的延伸，不新增组件、不加视觉元素）。
- 次文案 `.lineLimit(2)`，超出截断。**失败主文案 `.lineLimit(3)` + `.help(全文)`**：3 行给出行高上界，`.help` 保住完整原文。理由：失败原因含可变长插值（`\(detail)` 为路径 / 错误描述，长度无上界）——2 行在 480pt 下余量仅 7–11 字，截掉的正是「为什么失败」（ui-visual 实测）；而完全放开会让含整段 stderr 的文案跑到 4–6 行、单行高 100pt+，批量 3 行同时失败即把整节撑成长滚动（ui-standard 实测）。3 行 + `.help` 是两侧的交点：**截断不再是唯一信息通道**。失败态行高可超 44pt（上限 = 3 行）。
- **命令块是通用子块（REV-07，D-5.5）**：触发条件按**内容**判定——行内凡含**可粘贴执行的确切命令**，一律以独立命令块呈现；来源有二：`failed` 的终端清理命令分支、`cleanupNeeded` 的清理命令。样式 = `.font(.system(.caption, design: .monospaced))` + `.secondary` + `.textSelection(.enabled)` + `.help("可选中复制完整命令")`；**不为塞下而调小文本样式**（`.caption` 仍随 Dynamic Type 缩放，不得写成固定 `size:`）、不加底色或边框。copy-only 的复制内容只经剪贴板交付、不在界面呈现，故**不设命令块**；若将来在界面呈现，按 D-5.5 同形态。说明句仍走 `.callout` 次文案；「确切命令」必须可照抄执行（UX-10 / UX-28）。
- **命令块换行规则（REV-08，D-5.5）**：**禁止省略号截断**（`.lineLimit(nil)`、不设 `truncationMode`），允许自然换行，长 token 允许字符级断行，不做水平滚动。**命令块不计入「主文案 3 行 + 次文案 2 行」的行高上限，但单块 ≤3 行**；>3 行即回流另立条款，不得就地放宽。判定夹具：`remove` 命令（含 `--scope user`）claude 37 / codebuddy 40 字符 ≈0.7 行，**≤1 行**；无 CLI remove 的工具（Codex）以「需删除的配置键路径」为夹具，**≤3 行**；>3 行回流。**与路径块的异同**：同字体、同色、同可选中；**截断策略相反**——命令块不截断（D-5.5），路径块 `lineLimit(1)` + middle（D-5.3）。
- 大字号：名称折两行时图标槽与开关固定首行，行高随内容增长不裁切；**槽宽基准 16pt，随 Dynamic Type 同步放大**（`@ScaledMetric(relativeTo: .callout)`），不变式 = 槽宽 = 当前 callout 线盒宽，默认字号下即 16pt（r0.2 修：原「槽宽恒 16pt」在大字号下会裁切符号，与 9.5.2 的缩放声明矛盾）。
- **命令独立成行（硬约束，REV-07）**：文案含可粘贴执行的确切命令即触发命令块，来源有二——`failed` 的终端清理命令分支、`cleanupNeeded` 的清理命令。**命令不得嵌在「下一步：…」这类句子里**（句中命令既无法局部截断、也无法整体选中复制，且会被次文案的 2 行上限截断）。句式固定为：次文案第 1 行短句（「下一步：重试注册，或在终端运行：」）→ 次文案第 2 行或独立块承载命令。
- 减少动态效果：无自定义循环动画；焦点环用系统默认，不覆盖 `.focusEffect`。

**9.5.6 一致性核对与遗留**

- 复用既有事实：`SettingsView` `.frame(width: 480)` + `.formStyle(.grouped)`；statusRow 的「16pt 槽 + 8pt + callout 次文案」；`McpEscrowSettingsSection` 的 Label + orange 横幅；`FieldRowView` 的复制反馈与小号控件；`AttachmentSection` 的 `.help` 兜底；docs/22 §2 的 8/12/16 节奏、语义系统色、SF Symbols、≥24pt 点击区。

2. **折叠组不立组件条目**：系统默认 `DisclosureGroup` 承担 chevron / 缩进 / 行高 / 悬停，**零自定义样式可沉淀**，且当前唯一出现面——两条登记门槛都不满足，立条目即纸面规范。按「系统控件组合」处理。**回流条件**：出现第二个出现面，或任一处需要自定义（自定义 chevron / 展开动画 / 组内行背景差异），立即回流 DESIGN.md §11，组件名「设置页折叠组」，出处记本设计 §5.2 / §5.3 首次出现面。行为纪律不另立条款：VO 展开收起与计数播报归 §9.1，键盘可达归 UX-19。

   - **24pt 图标是对 D-7.2「40pt」的登记例外，已登记为 DESIGN.md D-7.2a**（节内嵌变体）：40pt 在整页 / 中列空态里是唯一视觉焦点，本节上方还有总开关 / 数据源 / 就绪状态，40pt 会与 Section header 抢层级（与 9.5.1 的 L1 降级同源）。其余三要素不变。登记行原文（DESIGN.md D-7.2a）：

## 11. 实现约束（供 dev-team，不含技术方案）

### 11.1 沙盒事实（约束，不是建议）

| # | 事实 | 对交互的约束 |
| --- | --- | --- |
| S-1 | App 沙盒读不到真实 HOME、不能 exec 用户 CLI | 探测与注册一律经非沙盒 helper（`CofferMcpHelper.app`），UI 不得假设 App 侧能直接读配置文件 |
| S-2 | helper 走**固定名** config / result 文件 | 同一时刻只允许一个操作在飞 → 必须串行队列（§11.3），这也是 `queued` 态存在的唯一原因 |
| S-3 | 结果靠轮询（≤15s） | 超时是常态失败之一，必须有 `failed` 与「重试注册」；UI 不得显示无限转圈 |
| S-4 | 关窗 / 取消任务后 helper 可能仍在跑 | 下次操作前清理残留 config/result（现有 registrar 已做）；UI 侧重进即重新 `checking` |

### 11.2 注册落点（dev 实现口径）

| 工具 | 探测信号 | 注册落点 | 移除方式 | scope |
| --- | --- | --- | --- | --- |
| Claude Code | `claude` 可执行 | `~/.claude.json` 顶层 `mcpServers.coffer` | `claude mcp remove coffer --scope user` | `user`（已冻结，`McpRegisterSpec`） |
| CodeBuddy | `codebuddy` 可执行 | `~/.codebuddy/mcp.json` 的 `mcpServers.coffer` | 对应 `mcp remove` 子命令 | 工具默认 |
| Codex | `codex` 可执行 | `~/.codex/config.toml` 的 `[mcp_servers.coffer]` + `[mcp_servers.coffer.env]` | 删除上述两表（**无 CLI remove**） | 无 scope 概念 |

- 注册值只有两项：`COFFER_VAULT_DIR` 与包内 `coffer` 路径。**无密码 env**，解锁走托管（docs/08 §7.1）。
- 服务器名三家统一为 `coffer`（唯一注册项，重注册即覆盖）。
- CodeBuddy / Codex 的确切 argv 形态由实现轮按各自 CLI 查证后冻结；UX 只约束「文案必须给出确切可执行命令，不得泛化」。
- **转义规则（REV-10，两种通道不可混用）**：
  - **shell 展示串（复制给用户粘贴）**：整值用单引号包裹，值内单引号按 `'\''` 转义；不做 JSON 转义、不做 TOML 转义。
  - **JSON 落盘（Claude Code `~/.claude.json`、CodeBuddy `mcp.json`）**：交给 JSON 编码器序列化，**不手拼字符串**；`COFFER_VAULT_DIR` 与命令路径作为独立字段值写入。
  - **TOML 落盘（Codex `config.toml`）**：字符串用基本字符串加转义（`"` 与 `\\`），或改用**字面量字符串**（单引号）承载含反斜杠的 Windows 风格路径；数组元素逐个转义。
  - **进程启动**：一律 argv 数组直传 `Process`，**不经过 shell**（沿用 `McpRegisterSpec` 纪律）；只有「复制给用户粘贴」的展示串才做 shell 转义。
  - 三通道共用同一组夹具：路径含空格、单引号、中文、`$`/`"`/`\\`（UX-31）。

### 11.3 串行队列（交互可见后果）

- 全局单队列，一次一个 helper 调用；排队中的行显示 `queued`。
- 队列顺序 = 用户操作顺序；批量操作为「一次性入队 N 项」，逐项推进，逐项落状态。
- 队列不跨页面会话保留：离开设置页即清空（未开始项直接丢弃，已开始项取消）。
