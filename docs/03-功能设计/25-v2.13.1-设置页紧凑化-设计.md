> 状态：**定稿待实现**（dev-architect，2026-10-24）。对应任务：18（本设计）/ 19（实现）。

## 0. 结论先行

1. **路线 = B**（`ScrollView` + `VStack` + 自绘紧凑卡片）。**A 在本机实测不可达目标**：卡片左右 20pt 与行左右 10pt 在 macOS 26 的 grouped `Form` 上**没有可用的公开 API** 可调，唯一生效的 `.controlSize(.small)` 只把行高 44→40（§3.1 有逐条实验数据）。
2. **窗宽 480 → 460**（不是 440）。目标规格下文本区宽仍为 **420pt**，与现状**完全相同** → 英文长文案、D-5.5 命令块行数、D-19.6 均**零回归**。
3. 目标：卡片外边距 20→12、行高 44/37.5→36/32、节距 10→8、页头/页脚留白 11.5/12/27→6/6/14、页顶页底 20→12；典型「单行 + 页脚」节高 **98 → 71pt（−28%）**。
4. 实现拆 **6 组**：G0 共享样式（前置，唯一新增文件）→ G1–G5 文件集互斥可并行 → G6 走查收口；合回 main 前 squash 成 1 提交（仓库纪律）。
5. **不可逆项 1 条**：Form→ScrollView 等于放弃系统 Form 的行为集（AX 分组语义 / 行 hover / key-view proxy / 系统节距），且子节全部改写后回退需 6 文件全量回滚 → **需人类确认后落定**（§6）。

## 1. 现状量化（本机实测，非「SwiftUI 默认值」引用）

### 1.1 测量方法（可复现）

现状设置页需要解锁密码库才能打开，无人值守下无法直接量。故用**同构复刻探针**：以 `NSHostingView` 承载与 `SettingsView.body` 同构的 `NavigationStack { Form { … }.formStyle(.grouped) }.frame(width: 480)`，runloop 转 1.4s 后取几何：

- **卡片与行的边界**：遍历 NSView 层级取 `_NSGraphicsView`（卡片背景层）与 `KeyViewProxy`（行内容锚点）的 `frame`；
- **页头/页脚与圆角**：`bitmapImageRepForCachingDisplay` 2x 渲染后逐像素扫描——按「卡片填充色 / 页背景色」判定卡片行区间，按「墨迹行」找文本上下边界，按圆角弧的逐行左缘偏移拟合半径；
- **变体实验**：同探针把候选 API 逐个套在 `Form` 上跑，比对卡片 `x/width`、行高、文档高。

复刻保真度：卡片 inset / 行高 / 节距 / 圆角 / 页头页脚留白全部取自同一套系统绘制，与真机设置页一致；**未覆盖**实际页面的额外内边距（如 `McpEscrowSettingsSection.swift:141` 的 `.padding(.vertical, 4)`）→ 实现期以 §5.1 的 AX 断言复核为准。

典型节高（单行 + 页脚）：**44 + 54 = 98 → 36 + (6+15+6+8) = 71pt**，−27pt（**−28%**）。10 节页面整体约缩短 250–300pt。

### 2.2 可点击性下限论证

- 系统与项目下限：D-13.5「交互元素 ≥24pt」；macOS 常规控件最小 24×24，列表行惯例 28–36。
- 目标值 **32（单行）/ 36（动作行）/ 44（双行）**，全部 ≥28（本次硬下限），且 32 / 44 恰好等于 D-11.4 已定稿的行高下界 —— **不是新造数值**。
- 32 与 36 的差别来自内容：Picker / Toggle 控件高 22–24（上下各 4–6 即 32）；Button 行需承载 `.bordered` 的 24pt 高与 hover 底色，给 6/6 留白（36）才不与相邻行粘连。
- **32/36 是行高下限而非定高**：`SettingsRow` 用 `.frame(minHeight:)`，Dynamic Type 放大时按内容增高（判据见 §5.1 第 3 行）。

### 2.3 窗宽结论：480 → 460（否决 440）

| 方案 | 卡片宽 | 文本区 | 名称预算（英文 MCP 工具行） | 与 5 个 480pt sheet | 结论 |
|---|---|---|---|---|---|
| 480（现状） | 440 | 420 | 176pt | 一致 | 左右留白只能靠 inset 收（§3.1 证明收不动） |
| **460（选）** | **436** | **420** | **176pt** | 父窗窄 20pt | 文本区不变 → **零 l10n 回归** |
| 440 | 416 | 400 | 156pt | 父窗窄 40pt | 技术可行，但收益仅 20pt，行数只增不减 |

数据支撑（本机实测）：

- 英文最长状态词 `Registered to another vault` = **163.8pt**（中文「已注册到其他库」91pt，D-11.8 的估算偏乐观）；最长工具名 `Claude Code` = **78.0pt**。即使退到 440（名称预算 136pt），名称仍不截断 —— 但收益抵不上下面的代价。
- 设置页会打开 5 个固定 480pt 的 sheet：`LicenseSettingsView.swift:66`、`RestoreBackupView.swift:86`、`VaultManagementView.swift:77`、`CrossCopySheet.swift:93`、`GeneratorSettingsView.swift:118`。父窗 440 会让 sheet 比窗口宽 40pt（视觉突兀），460 只窄 20pt；**统一 5 个 sheet 宽度是另一个任务，不在本版范围**。
- 321 字符的英文段落（MCP 节说明）在 420 / 380 / 366pt 三种宽度下均为 **3 行**（`caption` 11pt 实测），40 字符命令 `codebuddy mcp remove coffer` = **183.6pt** ≪ 366 —— D-5.5「命令块 ≤3 行」「remove 默认字号 ≤1 行」在 460 下余量最大。

退档条件（若评审要求更窄）：允许 440，**前置**为英文界面 10 节逐节截图核对（D-19.6）+ 把 5 个 sheet 宽度统一下沉为独立任务。

## 3. 路线取舍

### 3.1 路线 A：保留 `Form` + `.formStyle(.grouped)`，逐项覆盖 inset

本机逐条实测（同一夹具，窗宽 480，基线：卡片 `x=20 w=440`、单行高 44、节距 10）：

| API | 实测结果 | 判定 |
|---|---|---|
| `.listRowInsets(EdgeInsets(top:2,leading:4,bottom:2,trailing:4))`（含全 0） | 卡片 `x=20 w=440`、行高 44、内容起点 30 **全不变** | **无效** |
| `.environment(\.defaultMinListRowHeight, 24 / 28)` | 行高 44 不变 | **无效** |
| `.contentMargins(.horizontal, 8/12, for: .scrollContent)` | 卡片宽 440→432/416，**左边距恒 20**（只压右边） | **不可用**（非对称） |
| `.contentMargins(.leading, 8, …)` / `.trailing, 8` | 两种情况卡片都只窄 8pt、`x` 恒 20 | **不可用** |
| `.contentMargins(.vertical, 4, …)` | 几何完全不变 | **无效** |
| `.listSectionSpacing(_:)` / `.listRowSpacing(_:)` | **编译即 `unavailable in macOS`**（iOS-only 符号） | **不可用** |
| `.scrollContentBackground(.hidden)` / `.listRowBackground(Color.clear)` | 只影响绘制，几何不变 | **无效**（对密度无贡献） |
| `.padding(-8)` / `.padding(.horizontal, -8)` 套 `Form` | 卡片宽 440→456/464，**左缘仍 20**，向右溢出 | **不可用**（破对称、溢出窗口） |
| `.controlSize(.small)` | 行高 44→**40**、文档高 192→180；卡片 inset 与节距**不变** | **唯一有效** |
| `.formStyle(.columns)` / `.listStyle(.inset)` / `.listStyle(.plain)` | 卡片消失、内容落到 `x=186` 的列位，形态崩坏 | **不可用** |

**结论**：A 最多做到「行高 −4、页长 −7%」，**左右 20pt 与 10pt 完全动不了**，节距 54/56 也动不了 —— 恰好是用户抱怨的三项。**A 路线否决。**

### 3.2 路线 B：`ScrollView` + `VStack` + 自绘紧凑卡片

**与既有约束的兼容性（逐条核对）**

| 既有约束 | 现状实现 | B 路线下 |
|---|---|---|
| 标题栏红绿灯常驻、可随时关闭 | 设置是独立 Window scene（`CofferApp.swift:189`），红绿灯属**窗口标题栏** | **不变**：容器换成 ScrollView 不影响窗口装饰（`SettingsView.swift:28-33` 注释即此约束） |
| 滚动内容不得从标题栏透出（v2.4.1 用户反馈） | `.toolbarBackground(.visible, for: .windowToolbar)`（`:69`） | **不变**：该修饰符作用于窗口工具栏，与滚动容器无关；`NavigationStack` + `navigationTitle` 保留 |
| Liquid Glass 边缘 | `Form` 自带滚动边缘效果 | ScrollView 同样产生边缘效果；标题栏已强制不透明，观感差异须**目视复核**（§5.2-2） |
| 10 节单长滚动 + 内嵌子块 | 各子节返回 `Section` | 子节改返回 `SettingsCard`，内嵌 `VStack`（MCP 节）**原样保留** |
| 中英双语不截断（D-19.6） | 文本区 420 | 文本区**仍 420**（§2.3）→ 零回归 |
| Dynamic Type | `Form` 自动增高行 | `SettingsRow` 用 `minHeight` 下限 + 内容自适应 → 等价（判据 §5.1） |
| 节内空态 24pt 图标（D-7.2a） | `McpAgentToolsSection` 空态 | 不改；D-7.2a 禁的是空态自身再包卡片，与「容器是自绘卡片」不冲突 |

**代价（必须承认的 4 条）**

1. **失去 Form 的系统行为集**：AX 列表/分组语义、Button 行 hover 底色、key-view proxy 外壳、系统节内发丝线、系统节距。前三条需显式复刻（卡片 `accessibilityElement(children: .contain)`；hover 用 `.onHover` + 圆角底色，可选），后两条本来就是要改的。
2. **复刻绘制**：卡片填充、圆角、描边要从系统观感反推（实测填充 #F8F8F8 / 背景 #FFFEFE，Δ 6–7）。必须用语义色 + 目视，**禁止 hex**（D-11.6）。系统大版本升级后这些绘制可能漂移 → 每次 macOS 大版本复核一次。
3. **一次性代码量**：`SettingsStyle.swift` 约 200–320 行（度量 + 卡片 + 行 + 分隔线 + 无障碍），此后 6 个文件的节改用它。
4. **纪律成本（真正的长期成本）**：此后**任何**新增设置行都必须走 `SettingsRow`，禁止在业务文件里写裸 `padding(.horizontal, 12)` / `frame(height: 32)`。这条不进判据，各组就会各写一套 pt 慢慢漂走（§4.2-3 + §5.1 静态闸门）。

### 3.3 裁决

**选 B。** 理由按权重排序：① A 在目标维度上的能力为 0（左右与节距不可调，实测）；② 用户诉求的三项（左右、行高、节距）只有 B 能一起动；③ B 的代价集中在**一次性**（共享样式 + 复刻校验），A 的代价是**永久**（密度被系统锁死，以后每次想收紧都要重开这个讨论）。

## 4. 组件契约与文件分组

### 4.1 共享样式契约（`macos/Coffer/Views/SettingsStyle.swift`，新增）

~~~swift
enum SettingsMetrics {                     // 设置页局部几何契约（边界声明见 §6-2）
    static let windowWidth: CGFloat = 460
    static let pageInset: CGFloat = 12     // 页顶 / 页底 / 卡片左右
    static let cardRadius: CGFloat = 12
    static let cardSpacing: CGFloat = 8    // 卡到卡
    static let rowInset: CGFloat = 8       // 行左右 + 发丝线 inset
    static let rowHeightSingle: CGFloat = 32
    static let rowHeightAction: CGFloat = 36
    static let rowHeightTwoLine: CGFloat = 44
    static let headerGap: CGFloat = 6      // 页头文本 → 卡片
    static let footerGapTop: CGFloat = 6   // 卡片 → 页脚文本
    static let footerGapBottom: CGFloat = 8
}

struct SettingsCard<Content: View>: View {
    init(_ title: LocalizedStringKey? = nil,
         footer: LocalizedStringKey? = nil,
         @ViewBuilder content: () -> Content)
}

struct SettingsRow<Content: View>: View {
    init(minHeight: CGFloat = SettingsMetrics.rowHeightSingle,
         showsDivider: Bool = true,
         @ViewBuilder content: () -> Content)
}
~~~

硬约束（实现时不得违反）：

- **零依赖**：不引用 `AppModel`、不调 FFI、不进 `@EnvironmentObject` → 单文件可编译，这是 §5.1 探针判据成立的前提。
- `SettingsCard` 内部顺序：标题（`.subheadline.weight(.semibold)` + `.secondary`）→ `headerGap` → 卡片（圆角 `cardRadius`、语义填充、行间 `Divider().padding(.horizontal, rowInset)`）→ `footerGapTop` → 页脚（`.caption` + `.secondary`）→ `footerGapBottom`。
- `accessibilityElement(children: .contain)` + 卡片标题作分组 label（补回 Form 的分组语义，§7-R3）。
- 行高一律 `minHeight` 下限，不写 `.frame(height:)`。

### 4.2 按文件切组（与任务 19 对齐）

| 组 | 文件范围（唯一写者） | 内容 | 依赖 |
|---|---|---|---|
| **G0** | `macos/Coffer/Views/SettingsStyle.swift`（**新增**） | 度量常量 + `SettingsCard` / `SettingsRow` + 发丝线 | 无。**必须最先合入并冻结 API** |
| **G1** | `Views/SettingsView.swift` | 骨架 `Form`→`ScrollView`+`VStack`；10 节容器改写；窗宽 460；`securitySection` 的 `VStack` 包装层 | G0 |
| **G2** | `Views/LanguageSection.swift` | 语言行改 `SettingsRow` | G0 |
| **G3** | `Views/TouchIDSettingsSection.swift`、`Views/RecoveryCodeSetupSheet.swift`（`RecoveryCodeSettingsSection` 在 `:34`） | 三态节 + 恢复码节 | G0 |
| **G4** | `Views/McpSettingsView.swift`、`Views/McpEscrowSettingsSection.swift` | MCP 主节 + 托管三态节 + 命令块 / 状态行 | G0 |
| **G5** | `Views/McpAgentToolsSection.swift`、`Views/DropzoneAuthStatusView.swift` | 工具行 + 节内空态 + 放置区 `compact` 行 | G0 |
| **G6** | 无代码（走查） | 10 节 × 中英 × 深浅截图 + 判据回填 | G1–G5 |

并行规则（严格版，不含糊标注「可并行」）：

1. **G0 是唯一串行前置**：签名冻结前 G1–G5 不得开工（改一个 `init` 参数 = 5 组同时红）。
