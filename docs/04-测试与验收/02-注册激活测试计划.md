## 0. 使用说明

1. **先红后绿**：与 `10-v0.2验收用例.md` §0 同纪律——所有自动化用例在实现合入前必须演示可失败，不能红的用例视为假用例，不进入核销。
2. **时间注入**：试用期与时钟回拨用例一律以注入时间（`now: i64` 参数 / FakeClock）驱动，不 sleep、不等待真实 7 天。真机改时钟的人工项单列。
3. **自动化落点分两域（C-05 的直接推论）**：
   - **公开仓库可自动化**：门禁矩阵（注入双态 FakeGate）、错误码映射、cf-session / cf-ffi 契约——这些属于开源侧代码路径；
   - **私有仓库自测**：验签 / 试用期时钟 / 机器指纹 / Keychain 读写（cf-license 内部），测试向量以测试密钥签发；
   - **官方产物端到端**仅真机 / 人工（公开 CI 无法构建含激活模块的产物）。
4. **门禁命令**：以 `09-版本开发计划.md` §4 为地基（`cargo test --workspace --no-fail-fast`）。私有仓库测试不在公开门禁内，其绿是官方产物的交付前置（官方 CI 引用）。
5. **判据优先级**：`01` 验收要点 > `03` §14 设计裁决 > 本计划。冲突升级 team-lead。
6. **优先级口径**：FR-15.1 ~ FR-15.8 全组为 Must（`01` §7），本清单 46 条**全部为门禁**，不再单列优先级列。

### 1.2 不测范围（X-13 诚实声明，必须先读）

**对抗性测试一律不做。**本计划不验证、也**不应**验证：

- 绕过门禁的难度（不测试「逆向官方二进制篡改判定」的可行性）；
- 二进制完整性自校验 / 代码混淆 / 反调试（X-13 明确不做，无此能力即无可测对象）；
- 「删除 Keychain 记录重置试用」的防护强度——这是**接受的已知限制**（`03` §14.3 诚实声明），登记为 TC-TRL-06 的预期行为而非缺陷；
- 自编译免费版路径（R-09：确定存在且被接受）的封堵效果。

本计划验证的是**正确性与失败安全**：判定对（验签 / 计时 / 门禁矩阵）、退化安全（异常一律只读侧、绝不锁数据）、边界诚实（能力残缺处写透，对齐 FR-6.5 传统）。

## 4. 未覆盖项声明（诚实清单）

- **对抗强度不测**：见 §1.2——X-13 范围内的对抗性验证全部缺位，这是**设计决定**不是遗漏；
- **官方产物端到端**：公开 CI 无法构建含激活模块的产物，TC-CRD-01~03 / TC-SEC-03 / TC-BLD-03~04 依赖官方构建与真机，在私有仓 + 官方 CI 就绪前以 ⏳ 挂起；
- **Keychain 打桩保真度**：私有仓对 Keychain 的失败注入是 mock 层面，与真实 SecItem 异常（权限弹窗拒绝、-34018 类错误）可能有偏差，真机项部分补偿；
- **换机 / 超台数申请（Q-17b，2026-09-28 拍板）**：一码多机由**签发侧 N 枚签发**实现（默认 N=3 可调，`03` §14.2.1），属签发方人工台账流程，无自动化判据；测试计划覆盖的 App 侧语义为「他机序列号被拒」（TC-SER-04）；
- **7 天真实时间流逝**：全部以时间注入验证，真实 7 天流逝行为由 TC-TRL-07 真机首启 + TC-CLK-04 真机改时钟抽查，不做 7 天实等回归。
