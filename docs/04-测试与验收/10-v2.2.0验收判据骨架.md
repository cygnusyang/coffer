## §0 范围与总开关

- **本版定位**：v2.2.0 = docs/02-研发计划与决策/02-版本开发计划.md §2 版本卡的四个工作项：
  ① **MCP 解锁托管**（lead 裁定路线：HKDF 派生 `mcp_key` 托管而非主密码本身；`VaultEscrowStore` trait + macOS Keychain 实现，Linux/Android 留端口）；
  ② **设置页 provider 翻转收口**（切换放开 / 自家库配置 / 注册命令随 provider 生成 / op 告警条件化）；
  ③ **CLI 取密回退**（托管条目优先 → `COFFER_VAULT_PASSWORD` env 兜底 → 都无退出 1）；
  ④ **LOW-1 核销**（UDS accept 后无读超时，v2.1.0 顺延，docs/04-测试与验收/09-v2.1.0验收判据骨架.md §7）。
- **必须落档的语义（docs/02-研发计划与决策/02-版本开发计划.md 卡片裁定，不依赖设计细节）**：
  - 托管的是 **HKDF 派生的 `mcp_key`**，不是主密码本身——MCP 进程获得「此库读取能力」而非可复用主密码；
  - **换主密码不自动吊销托管**（DEK 不变 → mcp_key 不变）；吊销走设置页开关**显式执行**；
  - 平台层 `VaultEscrowStore` trait（LicenseGate 端口模式先例：cf-keychain）；macOS = 数据保护 Keychain（`WhenUnlockedThisDeviceOnly` + **无 ACL** + 共享访问组 A6DS985SJJ.app.coffer.Coffer，service `cn.coffer.mcp-escrow` / account=vault_uuid——**D-2 用户批准冻结，docs/03-功能设计/08-v2.2.0设计-MCP解锁托管.md §8**；「仅 coffer 可读」由访问组 entitlement + CLI 同身份同组签名两层达成，D-6 spike 前置）；Linux 端口预留（Secret Service → 内核 keyring 回退 → 均无则拒绝，**不落明文文件**）。卡片旧措辞「ACL 限 coffer 二进制」已在 7d1d4cd 对齐 D-2，差异核销（§6⑨）。
- **出口判据**：§1~§5 全部通过 = 本版 PASS。D-1 冻结面零改动为最高优先（全量门禁回归全绿为前提）。
- **诚实边界**：Swift / UI 侧无自动门禁（仓库无 CI，docs/02-研发计划与决策/02-版本开发计划.md §4 纪律③）——§4 判据一律标「手工」并给出可手工执行的步骤级判据；未实现项一律标 ⬜ 不标 ✅。

> **零网络语义**：本文引用「零网络 / 不联网」按 docs/02-研发计划与决策/03-不可逆决策追认表.md D-4 新口径——禁止外部网络为硬承诺；本机内 UDS / Keychain / 本机回环允许且不违背该承诺。托管 mcp_key 存平台安全存储（本机 Keychain）不违背零网络边界（数据不出本机）。
