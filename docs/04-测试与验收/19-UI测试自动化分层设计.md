## 0. 结论速览

1. **L1 可测 model 抽取**（首个目标 = `DropzoneImportView.swift:41-921`）：把 S0-S5 状态机整体抽为 `DropzoneImportModel`（ObservableObject，`macos/Coffer/Dropzone/DropzoneImportModel.swift`），视图降为薄壳。**关键收益**：docs/18 IT-12 明言「AppModel(@MainActor)+View 跨组件行为无 standalone 挂点，归走查+真机」——把 `.onChange(of: model.dropzoneBookmark)` 回落逻辑搬进 model 方法后，该判据从「走查」升级为「模型单测可覆盖」。顺带解决 dev-reviewer M-2（>800 行，921 行超限）。

4. **CI 矩阵**：L1 可 CI（swiftc CLI 无 GUI 依赖）、L2 可 CI（需 release 静态库前置）、**L3 恒 local**（需 GUI 会话 + AX TCC 授权，GitLab macOS runner 无 Aqua 会话，且 TCC 无法在无 GUI 下授予）。现状 `.gitlab-ci.yml` gate 只跑 `cargo test`，**22 套 Swift harness 全都不在 CI**——是否把 L1/L2 接入 CI 为 lead 决策项，非默认做。
5. **真机剩余**（用户裁定允许保留的人工面）：Touch ID 生物识别（Apple 不可脚本化）、首次 TCC 授权（AX driver 一次勾选）、真样采样一次（J-5）、A-3 跨重启持久性（RT-06）。

## 2. 实证记录（本机 2026-10-16 实测，非推测）

### 2.1 沙盒容器 UserDefaults 注入（L3 前置，已实证）

被测目标：`~/Library/Containers/top.cygnusyang.coffer`（dev build 与已装 App 共享同一 bundle id → 同一容器）。

```bash
KEY="coffer.uitest.probe.$(date +%s)"
# ① 读：defaults read 直接路由到沙盒容器（App 自己的窗口状态键可见）
defaults read top.cygnusyang.coffer "$KEY"   # 不存在 → exit 1
# ② 写：defaults write 落容器 plist（非全局 ~/Library/Preferences）
defaults write top.cygnusyang.coffer "$KEY" -string "probe-ok"
# ③ 容器真实 plist 含该键（strings 命中 1 次）；全局 plist 不存在（无混淆）
strings "$HOME/Library/Containers/top.cygnusyang.coffer/Data/Library/Preferences/top.cygnusyang.coffer.plist" | grep -c "$KEY"   # =1
# ④ 删：defaults delete 清理，读回不存在
defaults delete top.cygnusyang.coffer "$KEY"
```

**结论（已实证）**：`defaults write top.cygnusyang.coffer <key> <value>` 写进沙盒容器 store，App 内 `UserDefaults.standard` 读同一 store。L3 预置 `debugDisableTouchID`/`lastVaultUUID`/`coffer.testBaseDir` 均可走此路径。注：cfprefsd 有缓存，写前须确保 App 已完全退出（harness 先 terminate + 等待进程消失）。

### 2.2 AX 驱动可行性（L3 前置，已实证）

swiftc 编译的最小探针（`/tmp/coffer-ax-probe/probe.swift`，`-framework ApplicationServices -framework AppKit`）：
- `AXIsProcessTrusted() == true`（本会话环境已授辅助功能权限）；
- `AXUIElementCreateApplication(pid)` + `kAXWindowsAttribute` 枚举前台 App 窗口成功（iTerm2 窗口 role=AXWindow/subrole=AXStandardWindow/title 齐全）。

**结论（已实证）**：swiftc CLI 可作为 AX 驱动器，可 launch App、枚举窗口、遍历 AX 树、读 title/role/enabled、执行 AXPress、写 AXValue（文本输入）。细节（SwiftUI AX 暴露、NSOpenPanel 面板驱动）见 §5.4 待实证清单。

### 2.3 App 库目录与容器共享（L3 隔离的必要性，已实证）

- `AppModel.init`（AppModel.swift:550-552）：`baseDir = <documentDirectory>/Coffer`。沙盒下 `documentDirectory` = 容器内 `Data/Documents` → **dev build 与已装 App 共享同一真实库**。
- 无任何 baseDir 覆盖 seam（grep 无 env/UserDefaults 分支；仅 `debugDisableTouchID` 一个 debug seam 先例）。
- 后果：L3 不隔离就解锁驱动，等于操作**用户的真实库**（R2 红线 + 数据风险）。必须引入 `coffer.testBaseDir` seam（§5.3）。

### 3.2 依赖隔离（AppModel 面怎么隔离——契约 stub 先例）

`AppModel` 是 @MainActor + SwiftUI 重依赖，**不可 standalone 实例化**（docs/18 §4.x 已实证，用 `deriveStatus` 契约镜像规避）。L1 用**窄协议**隔离，参照 `DropzoneBookmarkTests/main.swift:68-74` 契约镜像先例：

```swift
// macos/Coffer/Dropzone/DropzoneImportContext.swift
/// model 需要的 AppModel 窄面（AppModel 在 extension 里 conform；测试用内存 stub）。
protocol DropzoneImportContext: AnyObject {
    var phase: AppPhase { get }
    var dropzoneAuthStatus: DropzoneAuthStatus { get }
    var session: VaultSession? { get }
    func setDropzoneBookmark(_ bookmark: DropzoneBookmark)
    func reloadItems()
}
```

```swift
// macos/Coffer/Dropzone/DirectoryWatching.swift
/// 目录监视窄面（DropzoneDirectoryWatcher conforms；测试注入 FakeWatcher 记录 start/stop + 受控 rescan）。
protocol DirectoryWatching: AnyObject {
    func start(watching url: URL, onEvent: @escaping () -> Void) throws
    func stop()
    func rescan() -> [URL]
}
```

- `DropzoneBookmarkStore`/`DropzoneFingerprintStore` 已有 `init(defaults:)` 注入（§4 已测），model 直接注入具体类实例（测试传 `UserDefaults(suiteName:)`）。
- `session` 走 `context.session`（真实 `VaultSession`）——harness 用 PuxRealSampleTests 骨架建临时库拿真 session（见 3.3）。
- `watcher` 走协议注入 FakeWatcher；`phase`/`dropzoneAuthStatus` 由内存 context stub 受控。

### 3.4 「View 薄壳 + 可测 model」通用模式定义（沉淀供后续 View 复用）

## 4. 设计题二：L2 fixtures 安全（R2 红线）

### 4.1 采样流程（用户一次 Touch ID 导出 → 本地核销 → 合成 fixture 入库）

```
[用户] Passwords.app 导出「所有密码」+ Touch ID 验证 → 放置区目录
   ↓（J-5 现有步骤，真机）
[probe] tools/run_dropzone_j5_sample.sh（本地一次性，不 commit）
   → 读真实导出 CSV（默认名随系统语言，实测 密码.csv），stdout 只出【非敏感】摘要：
     列头快照 / 行数 / 「导出所有密码」菜单名 / 默认文件名 / 重复导出命名（J-5 四核对）
     —— 密码列只计数不打印；测试密码走 env/文件不进对话/argv（R2）
   → 输出落 .local-samples/j5-sample-<date>.txt（gitignored）
   ↓
[dev-tester] 依据列头快照合成脱敏 fixture 入库：
   tests/fixtures/csv/dropzone_passwords_headers.csv（真实列头 + 假密码占位，2-3 行）
   文件头注释锚定「列头与 J-5 采样 <date> 一致，P-2 provisional」
   ↓
[L2 回归] run_dropzone_l2_regression.sh 用合成 fixture 跑全链路断言
```

### 4.2 入库与不入库边界（已实证既有设施）

| 载体 | 内容 | 是否入库 | 依据 |
|---|---|---|---|
| `.local-samples/` | 真样 `real-export-*.csv` / J-5 采样记录 | **否**（`.gitignore:81` 已忽略） | 含真实密码，R2 红线 |
| `tests/fixtures/csv/dropzone_passwords_headers.csv` | 真实列头 + 合成假密码 | **是**（`.gitignore:69-74` 已放行 `tests/fixtures/**/*.csv`） | 列头非敏感（J-5 四核对项之一）；密码为占位假值 |
| `tests/fixtures/*.1pux` | 合成样本 | 是 | 既有先例（sample_coverage.1pux） |

### 4.3 与 J-5 核销的配合

- J-5 是发版门禁（docs/18 §6：未过则 P-2 provisional 不得发版）。采样 probe 的 J-5 四核对输出 = 核销证据；合成 fixture 列头 = 核销产物。
- 若 J-5 采样发现列头与合成 fixture 不符 → 更新 fixture + 复核 P-2 Safari 别名映射（`dropzone.rs apply_header_aliases`，docs/18 §8 采 (a) 裁决）+ 重跑 L2。
- **不可逆标注**：fixture 列头是数据契约（冻结后驱动 P-2 别名映射与 L2 断言），J-5 核销前保持 provisional；核销后 lead 确认冻结。

### 4.4 L2 全链路断言面（对齐 PuxRealSampleTests 判据①②③）

临时库（mktemp + 前缀拦截）→ `createVault` → `openVault` → `unlock`（已知测试密码）→ 放置区目录放合成 CSV → `precheckDropzone` 断言计数/行序/`FfiDropzoneRow` 无密码字段（R2 类型层）→ `importDropzone(path:includeLineNos:)` 断言 `FfiCsvImportResult.importedRows` + `listItems` 落库逐字段 → 重复导入断言去重 → 文件漂移 fail-closed 零落库（docs/18 §3 已绿 18 例的 Swift 面复核）。

## 5. 设计题三：L3 AX 黑盒驱动器

### 5.1 形态与启动

- **形态（决策）**：swiftc 编译的 AX 可执行（ApplicationServices + AppKit），`macos/Tests/UIAXTests/main.swift` + `tools/run_ui_ax_tests.sh`。不用 osascript——AppleScript UI scripting 是 AX 的弱桥，能力与可断言性低于直接 AXUIElement API；且 TCC 授权对象不同（osascript 进程 vs 本 driver）。AX 路径已实证（§2.2）。
- **启动顺序**：
  1. `terminate` 已有 Coffer 实例（`killall Coffer` + 等进程消失；cfprefsd 缓存，先退再写 defaults）；
  2. 容器 defaults 预置：`debugDisableTouchID=true`（已有 seam）、`coffer.testBaseDir=<临时库>`、`lastVaultUUID=<测试库 uuid>`（键名 AppModel.swift:513）、可选预置指纹键（W-3/W-6 态）；
  3. `open macos/build/Coffer.app`（或 `NSWorkspace.launchApplication`）；
  4. AX 轮询 `top.cygnusyang.coffer` 进程 → `AXUIElementCreateApplication(pid)` → 找主窗口（AXWindows，排除 settings/AXSheet）→ 断言/驱动。

### 5.2 沙盒 UserDefaults 注入（已实证，§2.1）

注入键与用途表：

| 键 | 值 | 用途 | 状态 |
|---|---|---|---|
| `debugDisableTouchID` | true | 禁用 Touch ID 自动弹（AppModel.swift:970-981 既有 seam）→ AX 解锁确定性 | 已有 seam |
| `coffer.testBaseDir` | 临时库绝对路径 | 隔离真实库（§2.3 必要性） | **新增，需批准** |

### 5.4 TCC 辅助功能授权（实测结论 + 授权对象）

- **授权对象 = driver 二进制**（非 Terminal）。本机实证 swiftc CLI `AXIsProcessTrusted()==true`（§2.2）。
- **坑**：TCC 按「路径」记录（swiftc 无签名二进制）。driver 编译输出**必须固定路径**（`macos/build/axdriver/UIAXDriver`），不能 mktemp——否则每次路径变化 → 授权失效重弹。首次运行需用户本机在 系统设置→隐私与安全性→辅助功能 勾选一次（= 用户裁定保留的人工授权之一）。
- CI runner 无 Aqua GUI 会话 + 无法授予 TCC → **L3 恒 local**（硬约束，非仅「无显示器」）。

### 5.5 断言面

- 控件 existence：`AXUIElementCopyAttributeValue(kAXRoleAttribute)` + 子树遍历（role=AXButton/AXTextField/AXStaticText/AXSheet），按 title/label 匹配；
- label：`kAXTitleAttribute`（SwiftUI `.accessibilityLabel` → AXTitle；DropzoneImportView 已设 :541/:760，L3 用断言锚定防回归）；
- enabled：`kAXEnabledAttribute`（IT-01 锁定态入口 disabled / IT-21 N==0 导入按钮 disabled）；
- 窗口态：`kAXWindowsAttribute`/`kAXMainAttribute`/`kAXTitleAttribute`（W-2 锁定 → sheet 消失断言）；
- 动作：`AXUIElementPerformAction(kAXPressAction)`；文本输入：`kAXFocusedAttribute` + `AXUIElementSetAttributeValue(kAXValueAttribute)`（LockView 主密码框，复用 CofferApp.swift:388-392 同款扫描思路）。

### 5.6 L3 覆盖判据（docs/18 映射）

IT-01（E-1 三处入口 disabled 于锁定态 + 解锁可点）、IT-28（S0→S1→S2→S3→S4→S5 黑盒全流程 + S4 关闭禁用）、W-2 锁定停摆（真实 phase 相变）、S0 授权真流程（五要素声明 existence + NSOpenPanel 驱动 + 回 S1 目录行）、S5 删源警示文案（S-2）。**不覆盖**：Touch ID、首次 TCC、J-5 采样。

### 5.7 harness preflight（W4 前置，W3b spike 定稿）

驱动任意用例前必须跑 3 项自检，任一失败即 abort（fail-closed，不留半驱动状态）：

1. **AX 授权**：`AXIsProcessTrusted()` 须 true（false → 提示「辅助功能 TCC 未授权：系统设置→隐私与安全性→辅助功能→勾选 UIAXDriver」，exit 5）。
2. **目标窗口存在**：`kAXWindowsAttribute` 须返回非空且含 role=AXWindow 的真实窗口（不认 AXApplication proxy——窗口塌缩即锁定/异常信号）。
3. **content 元素非空**：主窗口子树须至少含 1 个 AXButton/AXTextField/AXStaticText/AXSheet 元素。

**锁定态门禁（W3b ③ 实证新增）**：macOS 屏幕锁定（`CGSSessionScreenIsLocked=true`，frontmost=loginwindow）时 AX 树塌缩为 AXApplication proxy、零 content 元素——preflight 第 2/3 项会命中。捕获到该态 → abort 并输出明确提示 **"needs unlocked GUI session"**（需解锁 macOS 屏幕后重跑），不得盲等/重试。判据：`ioreg -n Root -d1 -a | grep -A1 CGSSessionScreenIsLocked`。

另注（③ 实测）：SwiftUI Button 的 AXTitle 多为空，菜单项（AXMenuItem title 可见）与 StaticText 是更稳的断言锚定；AXSecureTextField 的 AXValue 一律净化 `<secure>`（R2）。

## 6. 设计题四：CI 可行性

- **现状**：`.gitlab-ci.yml` gate = `cargo test --workspace`（纯 Rust，headless 安全）；release = tag 触发全构建签名。**22 套 Swift harness 均不在 CI**（`run_gate.sh:31-38` 也只跑 cargo test/clippy/build/codesign）。
- **L1**：swiftc CLI 无 GUI 依赖 → **可 CI**（需 `libcf_ffi.a` release 静态库——gate job 只 `cargo test` 不产 release，接入需加 `cargo build --release -p cf-ffi` + `build_swift_bindings.sh` 前置）。
- **L2**：同 L1，FFI-linked → **可 CI**（同样需 release 前置）。
- **L3**：需 GUI 会话 + AX TCC → **不可 CI，恒 local**。
- **决策项（lead）**：是否把 L1（及 L2）接入 `.gitlab-ci.yml` gate。推荐**首轮不接**（与现状 Swift harness 惯例一致，全部 local），L1 接入作为后续低成本增量；避免扩大 CI 面与构建时间。`run_gate.sh` 语义不变；新增独立 `tools/run_ui_gate.sh`（L1+L2+L3 local 汇总，固定短摘要）供合流前本机跑。

> **lead 裁定（2026-10-16）**：采纳「首轮不接」——CI 面维持 cargo gate 现状，`run_ui_gate.sh` 为合流前 local 门禁；L1 接 CI 登记为后续独立决策项（不在本设计轮内默认实施）。
