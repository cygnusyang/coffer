## §0 范围与不变量

**本版一行意图**：把「注册目标」从写死 Claude Code 单点，泛化为**按 target 参数化的 3 家自动注册 + 5 家 copy-only 只读**，且 **Claude Code 既有行为逐字节不变**。

**非目标（判据不得据此判红）**：

- 不写 copy-only 5 家的配置文件（不探测、不写、无开关、无状态）；不为它们做动态发现。
- 不改 MCP 解锁托管节（`McpEscrowSettingsSection`）、不改注册值内容（仍只有 `COFFER_VAULT_DIR` + 包内 `coffer` 路径，**无密码 env**）。
- 不改 Rust 侧、不改 1Password（op）数据源分支的单行复制形态。
- 不改 helper 的三层取参（env → 固定路径 → argv）、固定名 config/result 文件名、15s 轮询预算。

**必须保持不变的不变量**（任一被破坏即判红，即使「多工具都能注册」）：

| ID | 不变量 | 依据 |
|---|---|---|
| INV-1 | 自动注册 target **恰好 3 家**，集合 = {Claude Code, CodeBuddy, Codex}；copy-only **恰好 5 家**，集合 = {Gemini CLI, Cursor, VS Code, Windsurf, Zed}；8 个 displayName 两两不同 | 设计稿 §2 表 |

## §1 先红基线与红→绿纪律

### 1.1 起草时的红形态（诚实说明）

实现未落地，TGT/ARGV/CFG/COPY/PROBE 引用新类型与新 spec 重载，在旧代码上**编译失败**。编译失败**不是**行为级红证明（它只证明「这些测试依赖尚不存在的 API」，不证明断言真的能捕捉错值）。

### 1.2 变异注入表（实现落地后必须逐族演示一次）

做法：临时改一处实现 → 跑 `./tools/run_mcp_registrar_tests.sh` → 确认**对应族**变红（且仅有该族红）→ 立即回滚 → 确认全绿。**回滚必须 `git diff` 确认为空**。

| 注入点 | 注入 | 期望变红的用例 | 若不变红则说明 |
|---|---|---|---|
| 任一 target 的 `isAutoRegister` | `true` ↔ `false` | TGT 对应用例 + PROBE-01（若 copy-only 被标 auto） | 该断言只做「存在性」检查，未断言取值 |
| Claude add argv 的 `--scope user` | 改成 `--scope project` 或删除 | ARGV-01 + REG-01 | ARGV 只做 `contains("--scope")` 弱断言（**现有测试即此形态**，见 §11-A5） |
| CodeBuddy add argv 的 `-e` | 改成 `--env` | ARGV-02（并须确认 Codex 仍绿，证明区分有效） | 未逐 target 断言 env 形参 |
| Codex remove argv | 加上 `--scope user` | ARGV-03 | 未断言「不得含 --scope」 |
| `~/.codebuddy/mcp.json` 优先级 | 反转为先读 fallback | CFG-02 | 用例只测单文件存在的情形 |
| TOML `[mcp_servers.coffer.env]` 解析 | 删掉 env 子表读取 | CFG-03 | 用例只断言 registered，未断言 vaultDir |
| VS Code 复制 JSON | `servers` → `mcpServers` | COPY-03 | 未断言键名（只断言可解析） |
| Zed 复制 JSON | `source: "custom"` → 删字段 | COPY-05 | 未断言键路径 |
| `performRegister` 的 auto guard | 把 `isAutoRegister` 判断移到 spawn 之后 | SAFE-01（走查项，见 §7） | 只做单元断言，未核查 spawn 前顺序 |

### 1.3 反向先红：REG-01 的双侧

REG-01 的期望是「旧绿→新绿」。证明它**能红**的方式不是让它在新代码上红，而是注入「Claude argv 改动」（§1.2 第 2 行）——若注入后 REG-01 仍绿，说明 REG-01 是恒绿断言，必须重写。

## §2 判据锚点与可测性前提

### 2.1 锚点纪律

- 一律以**文件 + 符号名（类型/属性/函数/check 名称）**锚，**不写行号**（行号随实现漂移，已在设计稿「引用约定」中确立）。
- 下文出现的 Swift 符号名（`McpAgentTarget` / `addArgv(target:…)` / `parseRegistration(data:target:)` 等）是**测试侧期望的调用面**，冻结前属「待对齐锚点」；若 dev 采用不同命名（如 `McpTarget`），**只更新锚点、判据不变**，并在修订记录注明。

### 2.2 可测性前提（判据成立的条件）

| ID | 前提 | 不满足时的处置 |
|---|---|---|
| TP-1 | 配置读取拆成**纯解析函数**（入参 `Data`/`String` + target，返回 `(registered: Bool, vaultDir: String?)` 或等价），IO 只做「读文件→喂解析」 | CFG-01~04 无法自动测 → 降级为「未覆盖」登记原因，**不得**以「代码看起来对」代替 |
| TP-2 | 命令构造为**纯函数**（target + vaultDir + 二进制路径 → argv / 复制串），不触 IO | ARGV/COPY 降级为走查 + 未覆盖登记 |
| TP-3 | 探测为**可注入存在性判断**的纯函数（不直接调 `FileManager` + `getpwuid`） | PROBE-01 降级为「仅真机覆盖」 |

## §4 ARGV：命令行 argv（单元）

> 前置（判据依据，不是用例）：CodeBuddy 与 Codex 的 `mcp add` 语法须有 **CLI 实测证据**（`<cli> mcp add --help` 输出片段）随实现提交。**没有实测证据的 argv 断言 = 猜的判据**，此时本组标「未覆盖（契约待证）」，不得记绿。
> 锚点建议：`McpRegisterSpec.addArgv(target:cofferBinaryPath:vaultDir:)` / `removeArgv(target:)` / `fullArgv(target:cliPath:cofferBinaryPath:vaultDir:)`，copy-only 入参返回 nil 或抛 `targetUnsupported`。

| 用例 | 判据（可判定） | 预期 | 实际 | 验证方式（锚） | 分级 | 状态 |
|---|---|---|---|---|---|---|
| **ARGV-01** Claude Code add | `addArgv(target: .claudeCode, …)` **逐元素等于** `["mcp","add","coffer","--scope","user","-e","COFFER_VAULT_DIR=\(vaultDir)","--",bundledCoffer,"mcp","--provider","coffer"]`；且 `fullArgv` = `[claudePath] + addArgv`（长度差恰为 1） | 完全相等（数组顺序敏感） | 待实现 | `McpRegisterSpec` 扩展用例 | 单元 | ⬜ |
| **ARGV-02** CodeBuddy add/remove | add 同形：含 `--scope user`、`-e`、`COFFER_VAULT_DIR=<dir>`、`--`、`<bin>`、`mcp --provider coffer`（serverName=coffer）；remove = `["mcp","remove","coffer","--scope","user"]`。**逐 target 断言 argv 元素**，不接受「大致包含」 | 两条均逐元素成立；`addArgv(.codebuddy)` ≠ `addArgv(.codex)`（防同一份 argv 被复用） | 待实现 | 同上 | 单元 | ⬜ |
| **ARGV-03** Codex add/remove（负形参） | add 用 **`--env`**：`COFFER_VAULT_DIR=<dir>` 作为 `--env` 的**下一元素**；**不含** `--scope`（断言 `!argv.contains("--scope")`）；remove = `["mcp","remove","coffer"]`，**不含** `--scope`、不含 `-e`/`--env` | 全成立（设计稿 §11.2「无 scope 概念」+ TASK-6 指令） | 待实现 | 同上 | 单元 | ⬜ |

**共用负向判据（三族都适用，不另立 ID）**：

1. **无密码**：任一 argv 元素不含 `PASSWORD`（大小写不敏感）。
2. **env 恰一份且形参正确**：`COFFER_VAULT_DIR=` 前缀元素恰 1 个；且前一元素必须分别是 `-e`（Claude/CodeBuddy）/ `--env`（Codex）——**只数前缀不查形参是静默失效**，见 §11-A6。
3. **注入面**：`vaultDir = "/v a u'e; rm -rf ~"` 时该值仍**整体**是单个 argv 元素（元素内**原样保留**，不做 shell 转义）；断言数组长度与基线一致、无元素被拆分；argv 里**不得**出现 `sh`/`-c`/`bash` 等 shell 元素。
4. **空值**：`vaultDir == ""` 的 register 必须先在 validate 阶段返回 `missingVaultDir`（不得构造出 `COFFER_VAULT_DIR=` 空值 argv 并 spawn）。

## §5 CFG：已注册状态解析（单元，依赖 TP-1）

> 锚点建议：`parseRegistration(data:target:) -> (registered: Bool, vaultDir: String?)`（JSON 与 TOML 各自实现，**同一 target 判定同一 schema**）；路径候选由独立纯函数给出（`configPaths(for:)`）。

| 用例 | 判据（可判定） | 预期 | 实际 | 验证方式（锚） | 分级 | 状态 |
|---|---|---|---|---|---|---|
| **CFG-01** Claude JSON（顶层 mcpServers） | 夹具 `{"mcpServers":{"coffer":{"command":"<bin>","args":["mcp","--provider","coffer"],"env":{"COFFER_VAULT_DIR":"/Users/me/Vault"}}}}` → `registered == true` 且 `vaultDir == "/Users/me/Vault"`（**逐字节相等**）；仅 `projects["/x"].mcpServers.coffer` 存在而顶层无 → `registered == false`（防把项目级条目误判为全局注册）；`mcpServers` 无 `coffer` 键 → `registered == false`；`coffer` 条目的 `env` 缺失 → `registered == true` 且 `vaultDir == nil`（**已注册但目录未知**，UI 必须按「目录 ≠ 当前库」处理，不得当作匹配） | 四条全部成立 | 待实现 | `McpRegistrarTests` 新配置解析组 | 单元 | ⬜ |
| **CFG-02** CodeBuddy 路径优先级 | 夹具：两份候选内容**不同**（`~/.codebuddy/mcp.json` 有 coffer 条目且 `vaultDir == "/A"`；fallback 候选有条目且 `vaultDir == "/B"`）→ 解析路径选择器必须给出 `mcp.json` 在前，结果 `vaultDir == "/A"`；仅 `mcp.json` 不存在时回落 fallback（`"/B"`）；两者都不存在 → `registered == false` | 优先级成立，且**不是**「读第一个能解析的」（要按路径存在性选，不是按内容合并） | 待实现 | 同上 | 单元 | ⬜ |
| **CFG-03** Codex TOML（表 + env 子表） | 夹具 `[mcp_servers.coffer]` + `command/args` + `[mcp_servers.coffer.env]` 下的 `COFFER_VAULT_DIR = "/Users/me/Vault"` → `registered == true` 且 `vaultDir == "/Users/me/Vault"`；缺失 `[mcp_servers.coffer]` 表 → `registered == false`；有主表无 `.env` 子表 → `registered == true` 且 `vaultDir == nil`；其它表（`[tui]` / `[[mcp_servers.other]]`）与注释、空行不得影响结果；值含转义（`COFFER_VAULT_DIR = "/a \" b"`）与字面量字符串（`'/a \ b'`，反斜杠不转义）均按 TOML 语义还原 | 全部成立；**不得**用「正则扫 `COFFER_VAULT_DIR` 字样」代替表定位（那会在 `[mcp_servers.other.env]` 上假绿） | 待实现 | 同上 | 单元 | ⬜ |
| **CFG-04** 损坏输入不崩溃 + vaultDir 提取口径 | 坏 JSON（截断 `{"mcpServers":{`、空文件、根为数组、`coffer` 值不是对象）与坏 TOML（`[mcp_servers.coffer` 未闭合、非 UTF-8 字节）→ **进程不崩溃、不抛未捕获异常、不死循环**，结论为 `registered == false`（或实现明确映射为 `checkFailed` 的失败态）；**绝不**返回 `registered == true`。另：`vaultDir` 提取须只取 `COFFER_VAULT_DIR` 一个键（`env` 里其它键不影响），值前后空白**原样保留**（不 trim，目录名可含空格） | 五类坏输入全部安全降级；vaultDir 逐字节等于夹具值 | 待实现 | 同上 | 单元 | ⬜ |

**关于 CFG-04 的判定边界（防假红）**：`registered == false` 与 `checkFailed` 的**取舍属 lead 待冻结项**（§12-C2）——实现任选其一都不得算缺陷，但**必须**满足：不崩溃 + 不判已注册 + UI 有可区分文案。测试在冻结前按「两者皆通过、并打印实际 code」处理。

## §13 缺陷登记承诺

- 实现缺陷 → 附「文件:符号 + 用例 ID + 判据原文」登记 `docs/01-KNOWN-ISSUES.md`，不越界改生产代码。
- 测试自身缺陷（用例写错 / 夹具不隔离 / 预期值算错 / 未经 `--help` 实测就写 argv 期望）→ 由测试侧改测试后重跑，**不转嫁**给 dev-coder。
- 重点区分三类「看起来像实现没做」的假红：① 新源文件未加入测试编译清单（A19，装配问题）；② 本机未装某家 CLI（PROBE/UI 环境项，用注入模拟而非真机）；③ 用旧 helper 产物验证（GATE-3 未跑就断言 argv）。
- **未登记 = 未发现**；**未覆盖 = 必须写进核销记录**（§14），不得以相邻用例冒充。

**覆盖自评（诚实）**：

- 正向：TGT、ARGV、COPY、REG、UI-02/03。
- 负路径：CFG-04（五类坏输入）、SAFE-01（copy-only 误调）、ARGV 共用负向判据（空值 / 注入值 / 无密码）、UI-03（跨 target 隔离）。
- 边界：TGT-01（集合 / 唯一性 / 顺序）、ARGV（`vaultDir` 含空格 / 引号 / shell 元字符）、COPY（三通道同夹具）、CFG-03（表缺失 / 子表缺失 / 转义 / 字面量字符串）。
- 安全：SAFE-02（无 shell 拼接）+ INV-4（无密码）+ 路径白名单（A20 既有断言保持）+ CFG-01「项目级不误判为全局」（防越权读）。
- 兼容：REG-01（Claude 逐字节零回归）、A20（正交纯函数仍绿）。

**未覆盖（明确列出，随发版登记，不得以相邻用例冒充）**：

1. **CLI 真实契约**（CodeBuddy / Codex / Gemini / Cursor / VS Code / Windsurf / Zed 的 `mcp add` 语法）——仓库内无这些 CLI，ARGV-02/03 与 COPY-01 的期望值来自 TASK-6 指令 + 官方文档，**未经本机 `--help` 实测**前标记「契约待证」。解除条件：dev 提供 `<cli> mcp add --help` 输出片段，或 CI 镜像装齐 CLI 做 argv 冒烟。
2. **UI-01~05**——需签名构建 + 真机；本机若仍为 0 valid codesigning identities，整节登记未覆盖（与 doc 20 §5 同一阻塞根因），不以单元断言替代渲染断言。
3. **helper IO 路径**（resolve 三家 CLI / spawn / 读回 confirm / 超时 terminate）——standalone 单测按项目纪律不覆盖 IO；由 GATE-3 产物核查 + 真机 UI-02/03 兜底，二者都缺时该路径**无证据**。
4. **串行队列与批量操作**（设计稿 §11.3：全局单队列、`queued` 态、批量不中断、在飞取消）——需可控时序的集成夹具，本版未立用例；触发条件：v2.12.x 出现「两个工具同时转圈 / 关窗后 helper 仍写配置」类缺陷时补。
5. **并发 / 多实例**：同一 target 被两个 App 实例同时注册（固定名 config/result 串场）——与本版改动面无交集（固定名协议未变），另立用例。
6. **Windows 风格路径 / 反斜杠 TOML 字面量字符串的真实回读**——CFG-03 只做解析级断言，未做「写 TOML → codex 真实读取」闭环。
