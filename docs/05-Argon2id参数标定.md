## 1. 为什么必须标定

本项目没有 1Password 的 Secret Key，因此 **Argon2id 参数是离线爆破成本的唯一来源**。参数不能拍脑袋定：

| 定低了 | 定高了 |
| --- | --- |
| 攻击者爆破成本不足 | 低端设备解锁要等好几秒，体验崩塌 |

标定方法见 `docs/03-详细设计.md` §2.3：固定 `t_cost=3, p_cost=4`，让 `m_cost` 从 64 MiB 起按档递增，选取在**最低端目标设备**上耗时落在 0.5–1.0 s 的最大值。

## 5. 分析

### 5.1 观察到的规律

耗时与 `m_cost` **近似线性**：

```
64 MiB → 137.6 ms
128 MiB → 277.0 ms   (2×   内存 → 2.01× 耗时)
256 MiB → 574.1 ms   (2×   内存 → 2.07× 耗时)
512 MiB → 1222.7 ms  (2×   内存 → 2.13× 耗时)
```

这是 Argon2 的预期行为（内存填充是主要成本）。**线性关系意味着可以外推**：若目标是 750 ms，约需 320 MiB。

### 5.2 为什么"384 MiB"不能作为最终值

三条理由，重要性递减：

#### 理由一：内存占用（最重要）

`m_cost = 384 MiB` 意味着**每次密钥派生要分配 384 MiB 连续内存**。

| 设备 | 影响 |
| --- | --- |
| M1 + 16 GiB | 无压力 |
| 低端 Android（2–4 GiB RAM） | **可能触发系统杀进程**，尤其在后台有其他 App 时 |
| 同上，且 `p_cost=4` | Argon2 内部再起 4 个线程，峰值内存与 CPU 占用进一步上升 |

这不是"慢一点"的问题，是**可能直接失败**。而失败发生在解锁时刻——那是用户最不能接受失败的场景。

#### 理由二：设备性能差距

M1 的单核性能约为入门 Android SoC 的 **3–6 倍**（量级估算，**待实测确认**）。

按此推算，384 MiB 在低端设备上可能对应 **2.5–5 秒**，远超 0.5–1.0 s 的目标区间。

#### 理由三：KDF 耗时不止发生在解锁

容易被忽略的一点——KDF 在这些场景都会执行：

| 场景 | 次数 | 用户感知 |
| --- | --- | --- |
| 解锁保险库 | 1× | 每次使用都发生，**最敏感** |
| 改主密码 | 2×（旧+新） | 低频，可接受较慢 |
| 创建新库 | 1× | 一次性 |
| 生物识别失败后回退主密码 | 1× | 失败时本就不耐烦，叠加延迟体验更差 |

解锁是高频操作，**它的耗时应以最严标准对待**。

### 5.3 预判

**低端 Android 设备的最终参数很可能落在 64–128 MiB 区间**，而非 384 MiB。

若实测发现 64 MiB 就已超出 1.0 s，则按 `docs/03-详细设计.md` §2.3 第 5 步**接受降级并在文档中记录**，不强行拔高参数。

> ### ⚠️ 连带影响：若最终参数显著低于 384 MiB
>
> 参数下降意味着**爆破成本下降**，这会削弱 `NFR-SEC-03` 的补偿效果（该条要求"通过提高 Argon2id 内存参数"来弥补缺失的 Secret Key）。
>
> 若出现这种情况，需要重新评估以下补偿手段是否充分：
>
> | 替代补偿 | 说明 |
> | --- | --- |
> | 强制密码强度 | 创建库时拒绝低熵密码（而非仅提示） |
> | 提高 `t_cost` | 用时间换内存，但同样增加解锁延迟，收益有限 |
> | 接受成本下降并明示用户 | 在威胁模型中如实说明，并建议用户使用高熵主密码 |
>
> **这件事必须在 M0 结束时给出结论**，不能拖到 v1.0 发布前。

## 7. 复现方式

```bash
cd core

# Markdown 报告（人读）
cargo run --release --example bench_kdf

# JSON（便于归档与程序比对）
cargo run --release --example bench_kdf -- --json

# 快速摸底（每档只跑 1 次）
cargo run --release --example bench_kdf -- --quick
```

> ⚠️ **必须用 `--release`**。debug 构建下 Argon2 会慢一到两个数量级，数字毫无参考价值。

标定时请一并记录 §3 的完整环境信息 —— **没有这些上下文，日后无法判断该参数在目标设备上是否仍然成立**。
