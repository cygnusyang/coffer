# 维护者交接与恢复手册（bus factor 缓解）

> 目标：让**没参与过本项目的人**在 1 小时内从零到能发一个版本。
> 本文所有步骤都在 2026-10-25 用「干净克隆」实测过一遍，结果见 §5。

## 0. 30 秒版

| 你要做的事 | 命令 |
| --- | --- |
| 拿代码 | `git clone https://github.com/cygnusyang/coffer && cd coffer` |
| 跑门禁（无需任何配置） | `bash tools/check_l10n.sh && bash tools/run_l10n_tests.sh` |
| 生成签名材料 | `./tools/make_provisioning_profile.sh`（需 Xcode 已登录 Apple ID） |
| 构建 | `./tools/build_macos_app.sh` → `macos/build/Coffer.app` |
| 发版 | 改版本号 + CHANGELOG → `git tag -a vX.Y.Z` → push tag → CI 自动出包 |

## 1. 前置环境

| 依赖 | 版本/说明 | 缺失时的表现 |
| --- | --- | --- |
| macOS | 14+（开发机实测 27.0.1） | —— |
| Xcode（完整版，非 CLT） | `xcode-select -p` 指向 Xcode.app | `swiftc`/`codesign` 缺失，构建即停 |
| Rust | ≥1.85（`core/rust-toolchain.toml` 固定） | `build_macos_app.sh` 第 1 步失败 |
| Apple ID 已登录 Xcode | 免费账号即可 | `make_provisioning_profile.sh` 报「请确认 Xcode → Settings → Accounts」 |
| Apple Development 证书 | `security find-identity -v -p codesigning` 至少 1 条 | 构建报「未找到 codesigning 身份（方案 A 要求 Apple Development 证书）」 |

> ⚠️ **不能用 ad-hoc 签名**：`keychain-access-groups` 是受限 entitlement，无证书时 App 写钥匙串必报 `-34018`（BUG-2 的历史结论，别再试）。

## 3. 发布流程（一步都不能省）

1. 改 `macos/Coffer/Info.plist` 的 `CFBundleShortVersionString`（**唯一版本源**）
2. `CHANGELOG.md` 顶部加 `## vX.Y.Z — YYYY-MM-DD` 段（release.yml 按此切 Release body，缺失会 fail）
3. `./tools/run_release_checklist.sh vX.Y.Z` —— 9 项检查，0 FAIL 才继续
4. `git tag -a vX.Y.Z -F <说明>` + `git push origin main vX.Y.Z`
5. 等 GitHub Actions `Release` 流水线（约 8–12 分钟）：构建 → 签名 → 打 dmg/zip → 发布
6. 产物三件套：`Coffer-vX.Y.Z.dmg` / `.zip` / `update-manifest.json`（OTA 用 zip）

## 4. 秘密与凭证（只记名字与位置，值不入库）

| 名称 | 用途 | 存放 | 轮换 |
| --- | --- | --- | --- |
| `APPLE_CERT_P12_BASE64` | Apple Development 证书 + 私钥 | GitHub Secrets | 证书过期前（约 1 年）用 `tools/export_ci_secrets.sh` 重导 |
| `APPLE_CERT_PASSWORD` | 上面 p12 的导出密码 | GitHub Secrets | 同上 |
| `APPLE_PROVISIONING_PROFILE_BASE64` | Mac App Development profile | GitHub Secrets | **7 天有效**，过期后 CI 构建直接 fail；重跑 `make_provisioning_profile.sh` 再更新 |
| `UPDATE_SIGNING_KEY_BASE64` | OTA 清单 Ed25519 私钥（32 字节种子） | GitHub Secrets | 更换会使已发布版本无法验签新清单，**慎换** |

本地对应物：证书在登录钥匙串；profile 在 `macos/build/top.cygnusyang.coffer.provisionprofile`（gitignore，不入库）。

## 5. 恢复演练记录（2026-10-25 实测）

**做法**：把仓库 `git clone` 到 `/tmp/coffer-handover`（模拟新人拿到全新副本），依次跑门禁、构建、发版检查单。

| 步骤 | 结果 | 说明 |
| --- | --- | --- |
| 干净克隆 | ✅ rc=0，44 MB | 克隆体量正常，无 LFS 依赖 |
| `tools/check_l10n.sh` | ✅ rc=0 | **零配置可跑** |
| `tools/run_l10n_tests.sh` | ✅ rc=0 | 零配置可跑 |
| `tools/build_macos_app.sh` | ❌ rc=1（预期） | 走到 3.5/4 才停，报错**精确可执行**：`缺少 provisioning profile（…/top.cygnusyang.coffer.provisionprofile）：请先运行 ./tools/make_provisioning_profile.sh 生成` —— 失败模式是好的，不需要猜 |
| `tools/run_release_checklist.sh v2.13.3` | ❌ 1 FAIL（预期） | 克隆里没有产物 → 「产物签名校验失败」；这是检查单正确行为 |

**结论**：新手在**零配置**下能跑到「只差 profile」这一步，且报错自带修法。补上 profile 后即可完整构建——这正是本文 §0 的 4 步。

## 6. 已知坑（踩过的，别再踩）

| 坑 | 现象 | 规避 |
| --- | --- | --- |
| profile 7 天过期 | CI 构建在 3.5/4 停：`provisioning profile 将于 … 过期，剩余 5h < 48h` | 每次发版前先看 profile 到期时间；过期就重跑生成脚本并更新 secret |
| bash5 变量后接中文 | `EXP�: unbound variable`，CI 红而本机绿 | 脚本里变量一律写 `${VAR}`，紧邻中文更必须 |
| 本地化资源晚于签名 | `codesign --verify --strict` 失败 | 资源装配必须在 codesign **之前**（build 脚本 3.4 步） |
| `.strings` 缺键 | 英文界面回落中文，**不报错** | 改完文案跑 `tools/check_l10n.sh`；存量用 `tools/l10n_reverse_check.sh` 清 |
| 占位符类型写错 | 英文界面静默回落中文（`UInt32` 写成 `%lld`） | 按声明类型写键：`UInt32→%u`、`UInt64→%llu`、`Int32→%d`；码位类一律 `%@` |
| 改完代码不跑门禁 | CI 红在本机复现不了 | 提交前至少跑 `check_l10n` + 相关 harness；`tools/run_gate.sh --changed` 可增量 |

## 7. 单点风险与缓解

- **现状**：单人维护（bus factor = 1）。代码、签名材料、发布账号、OTA 私钥都在一个人手上。
- **已做的缓解**：① 本文档（可执行步骤 + 实测记录 + 坑表）；② 全部决策有文档（`docs/02-…/03-不可逆决策追认表.md`）；③ 发布全自动（tag 触发），不依赖本机环境；④ 工作项板入库（`Coffer.kairo`）。
- **仍缺**：① secrets 的**托管备份**（当前只在 GitHub Secrets 与本机钥匙串，人不在就取不出来）；② 第二位维护者的最小权限（可发版但不能改 OTA 私钥）。
