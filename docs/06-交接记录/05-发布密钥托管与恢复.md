# 发布密钥托管与恢复（放在 Coffer 里）

> 解决运营门槛 T3-3.5 的第二个缺口：**发布材料只在一个人手上**（交接手册 §7 的「仍缺」）。
> 做法：把 4 个 CI secret 的备份写进 Coffer 库的环境容器 `coffer-release` —— 本地加密、不上云、可离线。

## 1. 存什么

| Secret 名 | 是什么 | 来源 | 轮换 |
| --- | --- | --- | --- |
| `APPLE_CERT_P12_BASE64` | Apple Development 证书 + 私钥（p12 base64） | 钥匙串导出（`tools/export_ci_secrets.sh`） | 证书约 1 年 |
| `APPLE_CERT_PASSWORD` | 上面 p12 的导出密码 | 导出时自设 | 同上 |
| `APPLE_PROVISIONING_PROFILE_BASE64` | Mac App Development profile | `tools/make_provisioning_profile.sh` 产物 | **7 天** |
| `UPDATE_SIGNING_KEY_BASE64` | OTA 清单 Ed25519 私钥（32 字节种子 base64） | 只在 GitHub Secrets，无法从产物反推 | **慎换**：换掉后旧版本无法验签新清单 |

## 2. 怎么存

```bash
./tools/backup_release_secrets.sh --dry-run   # 先看计划，不读值、不写入
./tools/backup_release_secrets.sh             # 逐项取值并写入
```

- profile 自动从 `macos/build/*.provisionprofile` 取；其余 3 项交互输入（密码类隐藏输入）。
- **值只经 stdin 传给 `coffer set-env`**，不进 argv、不进 stdout、不进日志；脚本只回显变量名。
- 写入落点是带 `coffer:environment` 标签的安全笔记条目 `coffer-release`（App 里能直接看到）。

## 3. 怎么恢复（换机器 / 交接）

1. 打开 Coffer，解锁，找到条目 **coffer-release**（标签 `coffer:environment`）。
2. 逐项复制，粘贴到 GitHub → **Settings → Secrets and variables → Actions**：`APPLE_CERT_P12_BASE64` / `APPLE_CERT_PASSWORD` / `APPLE_PROVISIONING_PROFILE_BASE64` / `UPDATE_SIGNING_KEY_BASE64`。
3. 本地构建另需两步（与 secret 无关）：`./tools/make_provisioning_profile.sh` 生成本机 profile + 确认钥匙串里有 Apple Development 证书。
4. 打一个 tag 验证流水线能出包（或 `gh run rerun <run-id>` 复跑上一次失败任务）。

> **为什么恢复要人工复制**：Coffer CLI 与 MCP 默认都**不能读出秘密值**（R2 纪律：密码只经 `run_with_secret` 注入子进程，不落 stdout）。这是设计取舍，不是缺功能。

## 4. 单点风险：Coffer 库本身

把发布材料收进 Coffer 只是把「散在人手上」变成「集中在一个加密库」，**新的单点变成了库本身**，必须配套：

| 措施 | 做法 |
| --- | --- |
| 库的加密备份 | App → 数据 → 备份，定期导出加密备份，放两处（外置盘 + 另一台机器） |
| 主密码可恢复 | 启用 Touch ID 解锁或生成离线恢复码（FR-17），否则库丢 = 材料全丢 |
| 极端兜底 | 证书可由 Apple 账号重签；**OTA 私钥换新会让旧版本无法验签**，所以这份备份比证书更重要 |

## 5. 验证清单

- [ ] `--dry-run` 通过，能看到 4 项计划
- [ ] 真实运行后，App 里能看到 `coffer-release` 条目，含 4 个变量名
- [ ] 记下 profile 到期日（7 天），到期前同时更新 GitHub Secret 与 Coffer 备份
- [ ] 库已有加密备份 + 恢复路径（Touch ID 或恢复码）
- [ ] 知道「OTA 私钥不能随意换」这条约束
