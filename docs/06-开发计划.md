## 1. 文档定位

本文件是项目**唯一的进度事实源**，回答三个问题：

1. **每条需求做了没有？** —— 见 §6 / §7 状态矩阵；
2. **项目整体走到哪一步了？** —— 见 §3 里程碑状态；
3. **接下来做什么？** —— 见 §9 近期工作重点。

**职责边界**：需求"是什么"看 `01-需求分析.md`，方案"怎么做"看设计文档，进度"做没做完"只看本文件。设计文档不承载进度信息。

**维护规则（强制）**：

- 任何需求状态发生变化（⬜ → 🟡 → ✅）的提交，**必须同步更新本文件的对应行与修订记录**；
- 每个里程碑状态跃迁时更新 §3；
- 状态判定以**测试为据**：标 ✅ 必须有对应测试通过；无测试支撑的状态一律标 🟡 或 ⬜。

**状态图例**：

| 标记 | 含义 |
| --- | --- |
| ✅ | 已实现，有测试支撑，行为符合需求验收要点 |
| 🟡 | 部分完成（骨架 / 局部路径可用 / 缺验收） |
| ⬜ | 未开始 |
| ➖ | 不适用或明确排除（见 `01-需求分析.md` §2.2 / MoSCoW Won't） |

## 5. Crate 实现状态

| Crate | 职责 | 状态 | 现有内容 |
| --- | --- | --- | --- |
| `cf-crypto` | KDF / AEAD / 子密钥派生 / 内存清零 | ✅ **可用** | Argon2id KDF（参数校验 + 预设档位）、XChaCha20-Poly1305 `seal`/`open`（含字段级 AAD 构造）、HKDF-SHA256 `derive_subkey`（一钥一用，7 用途常量，RFC 5869 + 独立 Python 交叉验证）、`Nonce::random`、`SessionKey`（zeroize） |

| `cf-audit` | 密码生成 / 安全检查 | 🟡 **仅两个函数** | `password_strength`（zxcvbn）、`generate_password`；Watchtower 主体（弱/重复/弱 URL/陈旧检测）未实现 |
| `cf-domain` | 条目领域模型 | ✅ **模型层可用** | 10 模块：22+ 类 `ItemCategory`（含 opvault 码映射）、字段/模板、快照、保险库、校验、错误码契约；50 测试。**持久化与 CRUD 编排未接**（属 cf-store/cf-session） |
| `cf-format` | 库文件容器格式 | 🟡 **主体已实现** | header.json 结构与校验、容器打开（版本三态）、MANIFEST 完整性清单、原子写（fsync→rename）；32 测试。**缺与 cf-store/cf-session 的集成与端到端建库验证**；版本迁移仅有三态判断（当前仅 v1，暂无迁移执行体，符合预期） |
