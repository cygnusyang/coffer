## 1. 排期原则

1. **每版都是能发给用户的增量**，不发「功能做了一半」的开发版。
2. **可控交付物不绑外部阻塞项** —— v0.2.0 定成导出而不是 Touch ID，就是因为后者卡在人类签名决策上，绑进去会一起卡死。
3. **有数据丢失风险的必须同版** —— 附件存储必须与 1PUX 导入同版（v0.3.0）：FR-7.8 会提示用户删除源导出文件，若附件还不能落库，删了就永久丢失。
4. **出口判据必须可执行**，一律以 §4 的门禁命令为地基。
5. **macOS 优先，Android 后置**。
6. **版本内不改已冻结的库格式（fmt-v1）**；确需改动属人类决策（D-4）。

## 3. 任务分解

### 3.1 编号规则

- 格式 **`vX.Y-Tnn`**，一个任务只属于一个发布版本；版本内从 `T01` 起编，**`T00` 保留给该版本的前置门槛**。
- **编号一旦分配永不重编**，任务取消则编号作废留空。
- **跨版本 / 跨文档引用必须带完整前缀**（commit message、`06` 修订记录、`KNOWN-ISSUES` 一律写 `v0.2.0-T03`，禁止裸写「见 T03」）—— `07` 与 `08` 的设计文档都用 T01~T05，裸引用必然撞车。

## 4. 门禁命令（所有出口判据的地基）

```sh
# 前提 1：cargo 可能不在 PATH 上（非交互 shell / 新终端 / 脚本）。
#         缺 PATH 时报 command not found、退出码 127 —— 命令根本没跑。
command -v cargo >/dev/null 2>&1 || export PATH="$HOME/.cargo/bin:$PATH"

# 前提 2：cargo 工作区根是 core/，不是仓库根（仓库根没有 Cargo.toml）。
cd core

cargo test --workspace --no-fail-fast          # 门禁（2026-09-27 实测：422 passed；另有 3 ignored = 1 条 KDF 人工独占 + 2 条既有 doctest）
cargo clippy --all-targets -- -D warnings      # 零警告

# 人工独占（不在门禁内）：1 GiB Argon2id 用例，debug 档会资源耗尽
cargo test --release -p cf-session --test adversarial 极端kdf参数建库记录与解锁往返 -- --ignored --test-threads=1

cd ..
./tools/build_macos_app.sh && codesign --verify --strict macos/build/Coffer.app
```

**三条纪律**：

1. **`--no-fail-fast` 必需** —— 不加它，首个失败目标即中止，后面 crate 与全部 doctest 一次都不跑，失败时会给出假绿。
2. **管道会吞退出码** —— `cargo … 2>&1 | tail -3` 之后 `$?` 是 `tail` 的，恒为 0。要真实退出码：不接管道，或 zsh 用 `${pipestatus[1]}`（1-indexed、小写），或先 `set -o pipefail`。叠加前提 1 就是**静默假绿**：命令根本没跑，门禁却显示通过。
3. **门禁只覆盖 Rust 侧 + 构建签名** —— `tools/build_macos_app.sh` 只做 `swiftc -O` **编译**（编译 ≠ 测试），`codesign --verify --strict` 验的是签名与包结构。**Swift / UI 侧行为没有自动门禁**（仓库无 CI），其 ✅ 标记的证据都在门禁之外，不代表已被自动验证。
