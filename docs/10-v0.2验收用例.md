## 0. 使用说明

1. **先红后绿**：本清单所有自动化用例在实现合入前必须演示可失败（对占位实现或注入缺陷运行），再对新实现确认通过。不能红的用例视为假用例，不进入核销。
2. **判据优先级**：`01-需求分析.md` 验收要点 > `09-v0.2实现方案.md` 设计裁决（§3 各节已评审冻结）。两者冲突时升级 team-lead 裁决。
3. **自动化落点约定**：
   - `cf-exporter/tests/{backup_loopback.rs, csv_export.rs}`（G1 产出，契约测试）
   - `cf-audit/tests/passphrase.rs`、`cf-audit/tests/watchtower.rs`（G2 产出）
   - `cf-session/tests/{change_password.rs, history.rs, search_fuzzy.rs, audit_orchestration.rs}`（G3 产出）
   - `cf-store/tests/history_repo.rs`（G3 仓库层）
   - 既有 `cf-store/tests/adversarial.rs`、`cf-session/tests/adversarial.rs` 模式沿用（密文落盘断言、strings 扫描）。
4. **测试纪律**：临时目录 / 内存 fixture、时间戳注入固定值（`now: i64` 参数已冻结在签名中）、随机用固定 seed 或统计断言、无网络。测试间零共享可变状态。
5. **性能阈值按 debug 构建放宽**：文档中阈值（如 200ms）为 release 基线；debug 跑法断言"单次平均 ≤ 阈值 × 50"或直接标注 `#[ignore]` 由 CI release 档执行。
