## 4. 工作流纪律（接手者必须遵守，全部来自既有裁定）

1. **git-flow**：从 main 拉 `feature/<名>` 分支开发；全部测试通过后尽快合回 main（禁止直接提交 main 的新功能）
2. **逐项闭环**：开发一个 → **独立验证**（fresh eyes 的第二代理或自证清单）→ 修 bug → 提交；不做大批量后统一测试
3. **门禁**（每次合流前）：`cd core && cargo test --workspace --no-fail-fast` + `cargo clippy --all-targets -- -D warnings` + `./tools/build_macos_app.sh && codesign --verify --strict`；注意管道吞退出码（假绿）
4. **FFI 纪律**：全同步、session_call panic 守卫、时间戳 i64 Unix 秒、错误码冻结（UI 按 code 映射不解析 message）；改 FFI 后必须 `tools/build_swift_bindings.sh` 重生成绑定，且该批次内 Swift 任务不再触 Rust；**UniFFI 不支持元组**、usize 不跨 FFI
5. **Swift UI 纪律**（docs/07 §2.4）：慢调用 Task.detached；错误 ErrorPresenter→lastErrorMessage→.ffiErrorAlert；**sheet 必须有显式关闭出口**（BUG-3/5 三例教训）；明文即用即弃
6. **文档同步**：状态跃迁同 commit 同步 docs/06 / docs/09 / README 三处；缺陷必登记 KNOWN-ISSUES（未登记 = 未发现）
7. **验收模式**：优先接口自动化（仿 `ClipboardTierTests`：FFI 驱动 + 临时目录 + 环境自恢复），真机人工项集中列 docs/13
