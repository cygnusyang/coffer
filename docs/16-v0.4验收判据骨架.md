## 1. 负路径与边界清单（方向级清单 r1.0 建立；r1.1 已按 `15` r1.2 补入接口级判据）

> 每条判据的反面至少列一个待覆盖方向。错误码沿用既有码空间（`15` §0 结论 2：候选码 1013 仅在实现证明需要时启用）——骨架只写方向，不预分配错误码。

### 判据① 反面

- 锁定态下执行复制 / 搜索被拒（未解锁错误路径，预期复用既有锁定语义错误码）。
- 搜索无命中 / 空查询 / 超长字符串 / Unicode（emoji、CJK、组合字符）输入不崩溃。
- TOTP 序列复制被打断：8 s 内手动复制别的内容 → TOTP 仍按时落剪贴板（有意覆盖，changeCount 守卫交接，`15` §3.3.6 测试 4）；待复制期间锁定 → TOTP 复制取消；三定时器（密码清除 / TOTP 延迟 / TOTP 不清除）互不干扰。
- 无 TOTP 条目不触发第二段复制。
- 快捷键与系统 / 其他 App 冲突时的行为（真机观察项）。

### 判据② 反面

- 关窗后进程被误退出（驻留失败即判据②直接失败）。
- 运行时 socket 清点非零即失败——须区分「清点方法自身误报」（清点命令的阳性对照：对一个已知有 socket 的进程跑同命令，确认能命中）。
- 重开窗口后锁定态语义漂移（关窗不得绕过锁定）。

### 判据③ 反面

- 目标库未解锁 / 已锁定时跨库复制被拒（`copy_item` 锁不双持设计的门禁面）。
- 自我复制（src == dst）语义：同库（dst 即 src 注册表同一实例）**内核允许**（产生副本）、**UI 层禁止**选择当前库（`15` §3.2.2）——双层语义分别钉住。
- 目标库锁定 → CrossCopySheet 内嵌解锁：错密码 1002 不继续复制；复制完成后目标会话立即 `lock()`（**复制即锁**：完成后 `is_unlocked == false`，单活跃不变量回归，`15` §3.2.4 测试 3）。
- Trashed 条目跨库复制 → 目标库产物为 Active（内核语义；UI 复制入口在回收站不可达，双保险，`15` §3.2.4 测试 4）。
- 冲突语义（r1.0 此处「待 15」已消除）：不存在「同名/同 uuid 冲突拒绝」路径——copy_item 恒产生新 uuidv7 产物；UI 层排除当前库即结构上排除同库选择（`15` §3.2.2）。
- 复制中途失败：Err 路径孤儿清理（内核 r2.5 交付项）、双库事务一致性（源库不残留半状态）。
- `cleanup_orphans` 单会话假设声明（docs/09 r2.5 审查 MEDIUM 项）在多库场景下的适用边界。

### 判据④ 反面

- 附件超大小上限（内核 MAX_ATTACHMENT_BYTES = 100 MiB）→ 1012，且 `attachments/` 目录无残留文件（快失败先于任何 IO，`15` §3.1.5 测试 2）。
- 锁定态四方法全部 1001；条目不存在（add/list）→ 1011；行不存在（read/remove）→ 1012；行在文件被外部删除 → 1005（`15` §3.1.5 测试 3）。
- 边界声明钉住（`15` §3.1.2）：`add_attachment` 只校验条目存在、**不限制条目状态**（Trashed/Archived 态有意收窄的 v0.4 边界）；同文件名不判重（1PUX 导入同语义）。
- 硬删级联：条目挂 2 附件 → hard delete → 行消失且两个旁路文件消失；软删 → 文件仍在、恢复后可读（`15` §3.1.5 测试 5）。
- 损坏附件密文读取失败且不落明文。
- 导出目标路径不可写 / 路径替换攻击方向（导出文件名不含未净化用户输入）。
- 并发同条目附件读写的隔离性。

### 判据⑤ 反面与边界值

- word_count 边界：3 与 10 接受；2 与 11（及 0、UInt32 溢出向）拒绝 → 1012。
- 分隔符合法域（`15` §3.3.4 定稿）：**1..=3 个可打印字符**；越界（空、超 3 字符、含不可打印字符）→ 1012（镜像 `generate_password` 的 Validation 映射）。UI 侧暴露 `-` / `.` / 空格 / 自定义四选。
- capitalize / number_suffix 组合全排列的结构断言。
- 随机源不可用时（若设计有此路径）的失败行为。

### 判据⑥ 反面（门禁纪律，来自既有裁定，直接执行不新建）

- `--no-fail-fast` 必需（假绿防线）。
- 门禁在 `core/` 下跑（仓库根无 Cargo.toml，实跑 exit 101）；管道吞退出码——判读退出码用 `${pipestatus[1]}`（zsh）而非 `$?`。
- `--ignored` 须配 `--all-targets`。
- 新增测试严禁指向 App 沙盒真实库路径（`~/Library/Containers/app.coffer.Coffer/…`，`14` §5 明令）。

## 2. 测试基建约定（沿用项目既有模式）

1. **FFI 驱动 + 临时目录 + 环境自恢复**：仿 `macos/Tests/ClipboardTierTests` 与 `tools/run_clipboard_tier_tests.sh` 先例——Swift 侧经 UniFFI 绑定驱动真实 NSPasteboard / 真实定时器；Rust 侧集成测试用临时库。产物落 `mktemp -d` + `trap` 清理（`13` R-③ 的更严标准）。
2. **禁止指向 App 沙盒真实库路径**：`~/Library/Containers/app.coffer.Coffer/Data/Documents/Coffer/` 对任何新测试 / 脚本禁用（`14` §5 明令）。多库 / 附件 / 密码短语全部在临时目录建库验证。既有脚本的 `--vault-dir` 可选参数不作为新测试的依赖。
3. **确定性**：时间用注入固定值；随机输出（密码短语、密码生成）断言结构性质而非具体值；网络调用本架构为零（判据②即验证此），无 mock 需求。
4. **隔离性**：测试间不共享可变状态；Keychain 相关沿用 `tools/run_keychain_tests.sh` 的隔离先例。
5. **性能断言口径**：如涉搜索性能（D-10 万条实测为待决策项、非门禁），区分 debug/release 分档，断言单次平均而非批量总耗时；万条实测若排入 v0.4.0，另立测试项并声明口径。
6. **新脚本命名与落位**：`tools/` 下、`#!/usr/bin/env bash`、`set -euo pipefail`、退出码不经管道丢失，与既有两套验收脚本同风格。
