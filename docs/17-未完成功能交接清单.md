## 4. 工作流纪律（接手者必须遵守，全部来自既有裁定 + 本轮新增）

1. **git-flow**：从 main 拉 `feature/<名>` 分支开发；全部测试通过后尽快合回 main（禁止直接提交 main 的新功能；纯文档批可直提 main）
2. **逐项闭环**：开发一个 → **独立验证**（fresh eyes 的第二代理或自证清单）→ 修 bug → 独立 fix commit → 回发同代理 re-verify → APPROVE 后才算闭环；不做大批量后统一测试
3. **门禁**（每次合流前）：`cd core && cargo test --workspace --no-fail-fast` + `cargo clippy --all-targets -- -D warnings` + `cargo fmt --all --check` + `./tools/build_macos_app.sh && codesign --verify --strict`；⚠️ **管道吞退出码 = 假绿**（本轮实测踩坑：diff 失败但 `| head` 吞掉退出码后继续打了成功标记——校验链必须显式检查每步退出码）
4. **FFI 纪律**：全同步、session_call panic 守卫、时间戳 i64 Unix 秒、错误码冻结（UI 按 code 映射不解析 message）；改 FFI 导出面后必须 `tools/build_swift_bindings.sh` 重生成绑定（**第 1-2 步可在 Linux 跑**，`cargo run -p cf-ffi --features bindgen-cli --bin uniffi-bindgen`；第 3 步 swiftc 冒烟需 macOS），且该批次内 Swift 任务不再触 Rust；**UniFFI 不支持元组与 trait object**、usize 不跨 FFI
5. **Swift UI 纪律**（docs/07 §2.4）：慢调用 Task.detached；错误 ErrorPresenter→lastErrorMessage→.ffiErrorAlert；**sheet 必须有显式关闭出口**（BUG-3/5 教训）；明文即用即弃
6. **文档同步**：状态跃迁同 commit 同步 docs/06 / docs/09 / README 三处；缺陷必登记 KNOWN-ISSUES（未登记 = 未发现）
7. **验收模式**：优先接口自动化（FFI 驱动 + 临时目录 + 环境自恢复），真机人工项集中列 docs/13 / `16`
8. **FR-15 门禁扩展纪律**：cf-session 新增写用例**必须**经 `write_guard(LicensedOp::…)` 取状态守卫（TC-GATE-12 审读点）；矩阵外新操作组须同步 `LicensedOp` 枚举与 docs/03 §14.6；冻结错误码表（cf-domain `error_codes_match_design_doc_section_12`）新增变体四处同步缺一即编译失败/测试红
9. **长命令后台跑**：构建/测试等长命令默认后台执行（库主裁定），前台只留快速只读命令
