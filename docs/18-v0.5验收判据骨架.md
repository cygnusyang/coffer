## 0. M0-⑤ 分叉门（本版判据的总开关）

> 分叉判据原文引自 `09-版本开发计划.md` §2 v0.5.0 卡片。M0-⑤ 的定义见 `06` §M0：「Passkey 平台能力验证：真机 + 真实网站注册 Passkey」——它判定的是**平台能力是否存在**，不是 Coffer 实现质量；判定结果决定 FR-10 交付形态，**两条分支都是合法出口**，但分支 B（降级）属需求变更、须人类确认（D-5）。

| 分支 | 触发条件 | 出口判据 | 对本骨架的影响 |
| --- | --- | --- | --- |
| **A：M0-⑤ 通过**（全功能） | 真机「创建 Passkey → 登录真实网站」≥ 3 个网站各跑一次创建 + 断言闭环，**3/3 全部闭环** | FR-10.1~10.6 全量验收（§1 分支 A 判据映射） | 全量测试项激活 |
| **B：M0-⑤ 不通过**（降级） | 平台能力验证失败（任一环节结构性不可行：扩展签名 / 系统不认凭据提供者 / 断言无法完成） | 首版退化为 FR-10.1 导入 / 10.2 查看 / 10.5 删除，创建（10.3）与使用（10.4）顺延 | §1 分支 B 判据映射激活；**须人类确认降级（D-5），未确认前分支 B 不可单方面生效** |

**分叉门的执行纪律**：M0-⑤ 的执行记录（§0.1）是分支判定的唯一证据源；判定由 lead 汇报人类拍板，dev-tester 只产出记录与建议、不做降级裁定。

## 2. 负路径与边界清单（方向级；接口级细节待设计）

- **私钥暴露面**（FR-10.2 反面）：任何 UI 视图 / FFI 导出 / 日志路径不得出现 Passkey 私钥明文——对齐 `07` §4.2 明文暴露面诚实声明体裁；「不展示私钥」须有程序化断言（详情接口字段集白名单），非仅 UI 检查。
- **导入反面**（FR-10.1 反面）：含 Passkey 数据的样本导入失败 / 字段缺失时的错误路径；**不识别的 Passkey 数据不得静默丢弃**（对齐 FR-7.4「未知列不静默丢弃」既有判据精神）；损坏凭据数据导入的行为。
- **rpId 域绑定**：凭据与 rpId 的绑定关系在存储/查看/使用三面一致；域名不匹配场景的行为（**待设计**定边界后落断言）。
- **删除反面**（FR-10.5 反面）：删除后系统侧凭据与库内记录的清理一致性；删除失败路径不残留半状态（对齐内核孤儿清理既有纪律）。
- **密码保留反面**（FR-10.6 反面）：创建 Passkey 过程中任何失败点回退后密码字段完好（失败安全性，对齐跨库复制先锁旧改先开新的 reviewer 裁定精神）。
- **扩展签名/授权反面**：profile 过期（7 天窗口）、扩展签名校验失败、系统不认提供者——对应分支 B 的结构性失败信号，TC-PK-0-A/B 捕获后即触发分叉流程，不得「重试到通过」。
- **门禁纪律**：沿用 `16` §1 判据⑥反面全套（`--no-fail-fast`、`core/` 下跑、管道退出码、沙盒路径禁令）。

## 3. 测试基建约定

1. **自动化/真机边界预判**：内核存储、导入解析、FFI 面可自动化（仿 `16` 既有模式：FFI 驱动 + 临时目录 + 环境自恢复）；**凭据提供者扩展与系统交互无法 FFI 驱动**——创建/断言/系统注册全部真机，这是本版自动化占比显著低于 v0.4.0 的结构性原因，预判先行留档。
2. **签名/Profile 纪律**：扩展独立进程必须自带签名（`09` v0.5.0 卡片依赖行原文）；profile 7 天有效期、2026-10-04 到期——所有真机批次的强制前置是续期 + `codesign` 双产物核验（TC-PK-0-A）。
3. **禁止指向 App 沙盒真实库路径**（`14` §5 明令不回退）；临时库构造 Passkey 样本（样本形态**待设计**）。
4. **确定性**：签名计数器等递增值断言单调性而非具体值；真实网站闭环记录以截图 + 结构化记录模板双留痕。
5. **计数口径**：引用门禁读数声明 `filtered` ≠ `failed`；`--ignored` 须配 `--all-targets`；门禁在 `core/` 下跑。
6. **真实网站项不 mock、不 fixture 化**（r1.1 吸收）：TC-PK-0-C / TCA-3/4 的「≥ 3 个真实网站」是判据原文——本地 / 离线 passkey 测试服务可用于开发期调试，但**不得替代验收网站数**；验收记录须留网站清单与操作日期。
7. **真实凭据不进仓库**（r1.1 吸收）：真机项产生的真实 passkey 私钥 / 网站凭据一律不进 fixture 与仓库（隐私 + 确定性）；自动化 fixture 用合成 passkey 数据（编码形态**待设计**）。

## 6. 缺陷登记承诺
