## §0 范围与总开关

- **本版定位**：冻结+审计，无新功能（docs/09 §3 v1.0.0 版本卡）。范围 = 修复审计发现 + NFR-SEC-01~07 逐条验证收口 + 测试扩容（RFC 标准向量 / proptest / fuzz）+ docs/01 §8 验收标准逐条核对。
- **出口判据**（docs/09 §3）：
  1. 门禁连续 10 次零失败（协议见 §1.5）；
  2. 审计报告公开五域全覆盖（依赖 E-6 采购，§7 挂起）；
  3. CRITICAL/HIGH 修复后经审计方复验，且交付构建 == 被审计 commit。
- **总开关**：§1~§2 全部判据通过 = 本版 PASS；真机/采购/样本类外部依赖（§7）按「挂起不阻塞」处理，不进 PASS 判定，但须在汇报中显式点名未核销项。

### §1.5 门禁连续 10 次零失败协议（出口判据①）

- **跑法**（与 v0.6.0/v0.7.0 全量门禁同口径，`PATH=~/.cargo/bin`）：
  `cargo test --workspace --no-fail-fast -- --skip 极端kdf参数建库记录与解锁往返 --skip 千条搜索基线`
  两条排除理由：① 极端 KDF 参数用例为不可复现的挂起遗留（先红后绿已知），② 千条搜索基线为性能基线非功能判据。
  另加：Swift `swiftc -typecheck`（56 文件）、`tools/` 各测试器（generator defaults 32 / clipboard 20 / 1PUX real sample 缺样本跳过 / check_no_network）。
- **D-1 基线**：cf-mcp `mcp_acceptance` 约 23 项红 = v2.0.0 域已知基线（见 KNOWN-ISSUES D-1），**不计入失败**。
- **记录格式**（每轮一行，追加到门禁日志）：
  `round=N ts=YYYY-MM-DDTHH:MM:SS passed=NNN d1_red=NNN filtered=N ignored=N exit=0 note=...`
- **判定**：连续 10 轮零失败（D-1 基线红稳定、filtered/ignored 数与基线一致）即满足出口判据①；任一轮出现非 D-1 失败 → 归因（生产缺陷打回 coder / 测试缺陷改测试），修复后重新起计 10 轮。

## §3 测试基建

- cargo workspace 门禁命令（§1.5 口径）；`--no-fail-fast` 保证单 crate 失败不吞其余结果。
- Swift：`swiftc -typecheck -swift-version 5 -target $(uname -m)-apple-macos14.0 -import-objc-header macos/Coffer/CoreBindings/cf_ffiFFI.h`（zsh 不做未引用变量分词 → `find ... -print0 | xargs -0`）。
- tools/ 测试器：`run_generator_defaults_tests.sh`（32 项）/ `run_clipboard_tier_tests.sh`（20/20）/ `run_1pux_real_sample_acceptance.sh`（缺样本 fail-fast）/ `check_no_network.sh` / `run_gate.sh`。
- release 静态库 `libcf_ffi.a` 必须与 HEAD 源码同步（stale 会导致 Swift 测试器结果失真）。
- 全部长时命令后台 + 日志落盘 + 只读 tail 摘要。

## §4 上版回归口径

- v1.0.0 全量回归**必须重跑 docs/23 全部判据**（9 组 73 条 + 11 真机项）；真机项按 §7 挂起，本机可测项全跑。
- 基线：v0.7.0 门禁 **1029 passed / 23 D-1 红 / 2 filtered / 7 ignored**。
- **只增不减**：v1.0.0 新增向量/属性/顺延补测后，passed 数应 ≥ 1029 + 新增测试数；filtered/ignored 与基线一致或更少；出现回退即归因。
