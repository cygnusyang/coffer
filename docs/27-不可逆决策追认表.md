### D-1 附：具体契约全文（冻结对象）

#### 1. 四个 MCP 工具（tools/call）

| 工具名 | 入参（arguments） | 返回（content[0].text，JSON） | 说明 |
| --- | --- | --- | --- |
| `list_secret_names` | `vault?`（字符串，可省略） | `{"names":["OPENAI_API_KEY", ...]}` | 只返回名称列表，无元数据 |
| `list_secrets` | `vault?`（字符串，可省略） | `{"secrets":[{"name","id","category","updated_at"}, ...]}` | 只返回元数据，**无值** |
| `run_with_secret` | `{"secret","env_name?","cmd","args":[...],"cwd"?}` | `{"exit_code":0}` | 模式 B：把秘密值注入子进程环境变量后启动 `cmd args`；**值不进 Coffer/Agent 进程内存**；子进程非零退出不是错误，原样返回 exit_code |
| `get_secret_metadata` | `{"secret"}` | `{"name","id","category","updated_at","allowed_actions":[]}` | 只读元数据 |

> `secret` 参数语义 = Secret **引用**（op provider 下即 `op://vault/item/field` 引用串），**不是明文值**。任何工具的入参都不接受明文值（防 Agent 把值回传进协议）。

#### 2. CLI 签名

```text
coffer mcp [--provider op|coffer] [--uds PATH] [--log PATH] [--vault NAME] [--no-audit]
```

| flag | 语义 |
| --- | --- |
| `--provider op` | 1Password op CLI 作为凭据源（恒可用；缺省 = `$COFFER_MCP_PROVIDER`） |
| `--provider coffer` | Coffer 自家 vault 作为凭据源（仅 feature `coffer-store` 构建下可用；库路径/密码走 `COFFER_VAULT_DIR` / `COFFER_VAULT_PASSWORD`；`--vault` 该路径忽略） |
| `--uds PATH` | 监听 Unix domain socket 而非 stdio（**D-4 裁定：v2.1.0 实现**） |
| `--log PATH` | 日志落文件（缺省 stderr；stdout 永远只出协议帧） |
| `--vault NAME` | 默认 op vault（缺省 = `$COFFER_OP_VAULT`） |
| `--no-audit` | 关闭使用审计记录（缺省开启） |

**退出码**：`0` 干净退出；`1` 配置错误（未知 flag / provider 不可用 / 库缺失）；`2` 协议致命错误（帧解析死锁，如单行超 64KiB）；`3` 身份缺失（未登录，7002）。

**Agent 注册命令**（设置页「复制」按钮输出）：

```bash
claude mcp add coffer -- coffer mcp --provider op --vault <vault>
```

#### 3. 7xxx 应用层错误码表（已登记 docs/03 §12）

| 码 | 常量 | 用户可见提示 | 可恢复 |
| --- | --- | --- | --- |
| 7001 | `ProviderUnavailable` | 凭据源不可用：{细节} | 是（凭据源就绪后重试） |
| 7002 | `AuthRequired` | 需要身份验证：{细节} | 是（完成身份验证后） |
| 7003 | `SecretNotFound` | Secret 不存在或无权限访问 | 否 |
| 7004 | `SubprocessFailed` | 子进程启动失败 | 是 |
| 7005 | `InvalidParameter` | 参数无效：{细节} | 是 |
| 7006 | `InternalError` | 内部错误（细节不泄露） | 否 |

> 另有协议层标准码（冻结，非本项目新增）：`-32700` 解析错 / `-32600` 无效请求 / `-32601` 方法未找到 / `-32602` 无效参数 / `-32603` 内部错误。
> 纪律：7xxx 消息载荷不得含 Secret 值或可直接降低攻击成本的信息。

## D-4 `--uds` 传输——上（用户否决暂缓）❌→✅

**原建议**：MVP 只发 stdio；`--uds` 占位不实现，保住「App 运行时 0 socket」措辞零改写。
**用户裁定（2026-10-07）**：❌ 否决——**UDS 要上**。理由：v2.0 功能面存在多路由场景（浏览器内取密、任何本机用密端点），需要本机内多客户端/多端点通信。
**零网络边界重申（随本裁定生效，全仓措辞统一改写）**：

> **「不联网」的准确边界 = 本机不去云端（无外部网络、数据不出本机）**；本机内进程间通信（UDS / 本机网络）**允许**，且同样必须**只在本机回环内**，不对外联网。

**落点**：v2.1.0 实现 UDS 传输（含 docs/20 §3.6 防重放全套：peer 凭据校验 `getpeereid`、会话 challenge、消息单调 id）；措辞改写工单见文末附表。

### 附：UDS 缺陷收益对照（裁定依据留档）

| | stdio | UDS |
|---|---|---|
| 工作方式 | 客户端 spawn coffer 子进程 | coffer 常驻，客户端连本地 socket |
| 生命周期 | 绑定客户端进程 | 常驻可长存 |
| 客户端数量 | 一 spawn 一实例 | 多客户端共享一个实例 |
| 宿主要求 | 必须能 spawn 子进程 | 只需能连本地文件 socket |

UDS 补齐的能力：常驻「一次解锁多端共用」、不可 spawn 宿主（如浏览器扩展类）接入、本地多路复用。攻击面扩大由 §3.6 防护（peer 凭据校验 / challenge / 单调 id）对冲。

## D-5 OTA 最小零网络豁免（用户 2026-10-10 追认）✅

**内容**：v2.7.0 OTA 更新引入**最小零网络豁免**——用户触发更新检查/下载时，App 允许对 4 个硬编码白名单端点（`api.github.com` / `github.com` / `objects.githubusercontent.com` / `release-assets.githubusercontent.com`）建立短时 HTTPS 连接；常态（非更新时段）不持有 socket；更新始终手动触发、不静默。
**不可逆性**：零网络承诺是本项目核心可信度来源与审计叙事（NFR-SEC-07 / 判据② / C-01 / D-4 边界重申），放开即构成对该承诺的**永久修订——审计叙事不可撤回**。豁免收窄为最小且可审计（4 host 固定白名单 + 三道锁），不开放一般网络能力。
**用户裁定**：✅ **追认（2026-10-10）**——接受最小豁免（更新期 + 4 白名单端点 + 默认手动不静默）；同步修订 docs/01（X-11 / NFR-SEC-08）、docs/16（判据② / TC2-B）、docs/09（v2.7.0 卡）。
**威胁面与三道锁（docs/35 §2.2）**：
- **三道锁**：① entitlement 层 `com.apple.security.network.client = true`（沙盒总开关，无法按域限，只能应用层限）；② 应用层 Updater 模块 URLSession delegate 强制校验 host ∈ 白名单 + 强制 HTTPS，非白名单一律拒绝，网络代码仅在 Swift 侧（`tools/check_ota_whitelist.sh` 防漂移）；③ 行为层默认「手动检查更新」，启动静默检查默认关，常态不持有 socket。
- **威胁面**：MITM 篡改清单/产物（高，缓解 = 清单 EdDSA 签名 + 产物 SecStaticCode 验签 DR 主 + CDHash 次 + HTTPS + host 白名单）；DNS 劫持（中，系统 CA + 强制 HTTPS + 白名单拒绝任意域）；降级攻击（中高，清单 `minimumVersion` 拒装 + 「只增不减」纪律）；仓库/账号被攻陷（高，产物须同 TeamID + DR 签名，更新密钥与代码签名分离）；更新端点不可用（中，失败静默降级不阻塞 App 使用）。
**落点**：v2.7.0 OTA（docs/35 §6 契约冻结；清单 schema v1 + 白名单 4 host + Updater 公开接口 + 替换协议）。
