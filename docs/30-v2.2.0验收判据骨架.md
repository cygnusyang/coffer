## §0 范围与总开关

- **本版定位**：v2.2.0 = docs/09 §2 版本卡的四个工作项：
  ① **MCP 解锁托管**（lead 裁定路线：HKDF 派生 `mcp_key` 托管而非主密码本身；`VaultEscrowStore` trait + macOS Keychain 实现，Linux/Android 留端口）；
  ② **设置页 provider 翻转收口**（切换放开 / 自家库配置 / 注册命令随 provider 生成 / op 告警条件化）；
  ③ **CLI 取密回退**（托管条目优先 → `COFFER_VAULT_PASSWORD` env 兜底 → 都无退出 1）；
  ④ **LOW-1 核销**（UDS accept 后无读超时，v2.1.0 顺延，docs/28 §7）。
- **必须落档的语义（docs/09 卡片裁定，不依赖设计细节）**：
  - 托管的是 **HKDF 派生的 `mcp_key`**，不是主密码本身——MCP 进程获得「此库读取能力」而非可复用主密码；
  - **换主密码不自动吊销托管**（DEK 不变 → mcp_key 不变）；吊销走设置页开关**显式执行**；
  - 平台层 `VaultEscrowStore` trait（LicenseGate 端口模式先例：cf-keychain）；macOS = 数据保护 Keychain（`WhenUnlockedThisDeviceOnly` + **无 ACL** + 共享访问组 A6DS985SJJ.app.coffer.Coffer，service `cn.coffer.mcp-escrow` / account=vault_uuid——**D-2 用户批准冻结，docs/29 §8**；「仅 coffer 可读」由访问组 entitlement + CLI 同身份同组签名两层达成，D-6 spike 前置）；Linux 端口预留（Secret Service → 内核 keyring 回退 → 均无则拒绝，**不落明文文件**）。卡片旧措辞「ACL 限 coffer 二进制」已在 7d1d4cd 对齐 D-2，差异核销（§6⑨）。
- **出口判据**：§1~§5 全部通过 = 本版 PASS。D-1 冻结面零改动为最高优先（全量门禁回归全绿为前提）。
- **诚实边界**：Swift / UI 侧无自动门禁（仓库无 CI，docs/09 §4 纪律③）——§4 判据一律标「手工」并给出可手工执行的步骤级判据；未实现项一律标 ⬜ 不标 ✅。

> **零网络语义**：本文引用「零网络 / 不联网」按 docs/27 D-4 新口径——禁止外部网络为硬承诺；本机内 UDS / Keychain / 本机回环允许且不违背该承诺。托管 mcp_key 存平台安全存储（本机 Keychain）不违背零网络边界（数据不出本机）。

### §1.5 LOW-1 UDS idle 读超时（v2.1.0 顺延核销，docs/28 §7；lead 裁定 2026-10-07 落定语义）

> 缺陷本质：`core/cf-mcp/src/uds.rs::run` accept 后无读超时——连接方不发数据则 server 挂起至对端动作
> （availability-only，非安全缺口）。**lead 裁定（2026-10-07，§6③）**：修复 = **逐帧 idle 超时**——每收到
> 一个**合法帧**重置计时器；缺省 **120 s**；env `COFFER_MCP_UDS_READ_TIMEOUT_SECS`（秒）可配；**下限 10 s**；
> **不提供关闭**（fail-closed：LOW-1 的本意就是消除无界挂起）；challenge / initialize 握手阶段同受此窗约束
> （未完成握手的不活动同样超时断开）。**先红**：新测试在旧实现（无超时）上对「连接后不发数据 → 超时断开」
> 场景挂起/失败；对「按连接时长而非 idle 判定」「超时可关闭/无下限」的缺陷变体须转红。

| 判据 | 计划落点测试（先红依据） | 状态 |
|---|---|---|
| **idle 读超时触发断开**——连接建立后不发数据，超过超时值 → server 干净退出（不挂起；退出码可断言） | `core/cf-mcp/src/uds.rs` 计划新增 `uds_idle_read_timeout_disconnects`（模块级，短超时注入）+ `core/cf-mcp/tests/uds.rs` 计划新增集成版 | ⬜ 待实现 |
| **逐帧 idle 语义**——每收到合法帧重置计时器：帧间隔 < 超时值的慢速长会话不被断（对照 §1.5 下条「不误伤活跃会话」）；只有「超过超时值无任何合法帧到达」才断 | 计划 `uds_idle_timeout_resets_on_valid_frame`（短超时 + 帧间隔 < 超时值 → 会话存活；注入「按连接时长判定」变体须转红） | ⬜ 待实现 |
| **超时值可配 + 缺省 120 s + 下限 10 s + 不提供关闭**（fail-closed）——env `COFFER_MCP_UDS_READ_TIMEOUT_SECS`：`<10` 拒绝（配置错误退出 1）；缺省 = 120 s；不设「0 = 关闭」路径 | 计划 `uds_idle_timeout_default_is_120s` / `uds_idle_timeout_below_min_rejected`（注入 5s / 0s → 配置错误退出 1）；缺省值文档锚 = docs/20 §4.3 env 表增行 | ⬜ 待实现 |
| **不误伤活跃会话**——持续有数据流（含间歇合法帧）不被 idle 超时误断 | 计划 `uds_active_session_not_timed_out`（真实握手 + 帧间隔 < 超时的会话在超时窗后仍存活） | ⬜ 待实现 |
| **challenge/initialize 握手同受窗约束**——连接后不完成握手（不回显 challenge）同样超时断开（不因「还没到协议活动」豁免） | 计划 `uds_handshake_inactivity_times_out`（只连接、不 initialize → 超时断开） | ⬜ 待实现 |
| **超时断开后 socket 清理 + 退出码契约不破坏**——超时路径复用 0 干净退出（连接生命周期完成语义，对照 peer 拒绝路径） | 计划断言随 `uds_idle_read_timeout_disconnects`（退出后 socket 文件清理 + 退出码 0） | ⬜ 待实现 |
| **既有 UDS 防护全套回归不破**——§3.6 peer/challenge/单调 id/单次 connect/权限判据对应的现网测试全绿 | `core/cf-mcp/tests/uds.rs` + `src/uds.rs` 既有全量（回归；具体条数以门禁实测为准，docs/28 r1.2 记 17 条） | ✅ 回归保留 |
