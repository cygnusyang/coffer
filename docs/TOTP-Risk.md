## 风险等级定义

| 级别 | 影响 | 处理优先级 |
| --- | --- | --- |
| **Critical（关键）** | 导致安全漏洞、数据泄露或不可用 | 必须在发布前修复 |
| **High（高）** | 显著降低安全性或可用性 | 建议修复，可接受残余风险需批准 |
| **Medium（中）** | 影响体验但无安全风险 | 排入开发计划 |
| **Low（低）** | 理论风险或边缘场景 | 文档记录即可 |

## 风险清单

### R-01：时间同步偏差导致验证码失效

| 项 | 内容 |
| --- | --- |
| **类别** | 功能可用性 |
| **影响等级** | Medium |
| **触发条件** | - 用户设备时间与服务器时钟不一致（如未联网）<br>- 设备跨越夏令时切换<br>- NTP 服务临时故障 |
| **攻击场景** | 无直接攻击利用路径，仅用户体验问题 |
| **发生概率** | Low（现代操作系统默认启用 NTP 自动校准） |
| **缓解措施** | - RFC 6238 §4 共享窗口±1 分钟（3 个连续窗口 T-1、T、T+1）<br>- 用户界面提示"请检查系统时间"<br>- 锁定状态时暂停 TOTP 生成，避免错误码泄露 |
| **残余风险** | 若设备持续离线超过 2 分钟，验证码失效（符合 RFC 标准） |

### R-02：熵源质量不足（嵌入式设备）

| 项 | 内容 |
| --- | --- |
| **类别** | 安全性 |
| **影响等级** | Medium |
| **触发条件** | - 系统刚启动（early boot）<br>- 熵池耗尽（罕见，现代设备通常足够） |
| **攻击场景** | 攻击者可能利用 `getrandom` 返回错误时降级到伪随机源<br>但本项目**不降级**：失败则报错 |
| **发生概率** | Very Low（现代移动设备 CSPRNG 熵池充足） |
| **缓解措施** | - 复用 cf-crypto 的 `getrandom::fill()` 封装<br>- 失败时直接返回 `RandomUnavailable`，不降级<br>- 日志记录熵源事件供审计 |
| **残余风险** | 嵌入式设备上刚启动时随机数质量可能不足 |

### R-03：TOTP 密钥通过 cf-store 读取时泄露

| 项 | 内容 |
| --- | --- |
| **类别** | 加密存储 |
| **影响等级** | Critical（但可控） |
| **触发条件** | - `cf-totp` 从 cf-store 加载 TOTP 条目<br>- DEK 在内存中解密密钥材料 |
| **攻击场景** | - 进程内存转储分析<br>- 恶意代码注入读取进程内存<br>- Android root / macOS jailbreak |
| **发生概率** | Very Low（需突破应用沙盒） |
| **缓解措施** | - TOTP 密钥与条目字段同强度加密（DEK 派生子密钥）<br>- 内存操作后清零（`zeroize`）<br>- Android FLAG_SECURE / macOS 禁止截屏<br>- 解锁会话期间才读取 TOTP 数据 |
| **残余风险** | 根/越狱设备下内存保护失效；这是所有加密应用的固有残余风险 |

### R-04：防重放攻击未实现计数器持久化

| 项 | 内容 |
| --- | --- |
| **类别** | 防重放 |
| **影响等级** | Medium（需设计决策） |
| **触发条件** | - 验证码被录制并回放（如截屏 + 自动填充）<br>- 网络延迟导致计数器不递增 |
| **攻击场景** | 攻击者录制当前验证码，等待服务器接受后再重放 |
| **发生概率** | Low（单设备使用场景下罕见） |
| **缓解措施** | - TOTP crate 内部递增 HOTP 计数器<br>- 调用方在 cf-store 持久化计数器状态<br>- **设计决策点**：是否允许"过期验证码重试一次"？ |
| **残余风险** | 若禁用计数器保护，录制攻击可行；建议始终启用 |

### R-05：时序侧信道（截断计算）

| 项 | 内容 |
| --- | --- |
| **类别** | 时序分析 |
| **影响等级** | Low（可忽略） |
| **触发条件** | - 攻击者测量 HMAC 计算时间<br>- 利用 SHA-1 截断分支差异 |
| **攻击场景** | 理论上可通过大量样本推断部分密钥字节 |
| **发生概率** | Extremely Low（单点测量误差远大于实现差异） |
| **缓解措施** | - RustCrypto `hmac` crate 使用常量时间比较<br>- 若需更严格保护，可引入 `subtle` crate<br>- RFC 6238 未要求此级别防护 |
| **残余风险** | 理论风险，实际攻击成本极高 |

### R-06：SHA-1 哈希碰撞（理论）

| 项 | 内容 |
| --- | --- |
| **类别** | 密码学原语 |
| **影响等级** | Low（RFC 标准规定） |
| **触发条件** | - SHA-1 碰撞攻击<br>- 截断算法失效（极不可能） |
| **攻击场景** | SHAttered 攻击（2017）针对任意消息，对 HMAC-SHA1 无直接影响 |
| **发生概率** | Negligible（需计算能力远超现实可用资源） |
| **缓解措施** | - RFC 6238 明确规定使用 SHA-1<br>- HMAC 结构提供比纯哈希更强的碰撞抗性<br>- 如需更强哈希，可扩展 SHA-256/SHA-512 变体 |
| **残余风险** | 遵循 RFC 标准的实现无需担心；SHA-1 碰撞对 TOTP 无实际威胁 |

### R-07：URI 解析错误导致配置失效

| 项 | 内容 |
| --- | --- |
| **类别** | 可用性 |
| **影响等级** | Low |
| **触发条件** | - Base32 编码错误（大小写敏感）<br>- URI 缺少必需字段（`secret`）<br>- 非标准参数组合 |
| **攻击场景** | 无直接攻击利用路径，仅用户配置问题 |
| **发生概率** | Medium（用户可能手动编辑 URI） |
| **缓解措施** | - 明确错误消息指示修正方法<br>- Base32 大小写不敏感（`data-encoding` crate 已处理）<br>- 文档说明 URI 格式要求 |
| **残余风险** | 用户输入错误导致配置失败 |

### R-08：Base32 解码填充截断攻击

| 项 | 内容 |
| --- | --- |
| **类别** | 编码安全 |
| **影响等级** | Medium（罕见） |
| **触发条件** | - Base32 字符串末尾填充不足<br>- 恶意构造的截断密钥 |
| **攻击场景** | 攻击者利用填充截断生成部分匹配密钥 |
| **发生概率** | Very Low（正常 URI 无此问题） |
| **缓解措施** | - `data-encoding` crate 正确处理填充<br>- 校验解码后长度必须为 SHA-1 倍数（16/20/24...）<br>- 不匹配则拒绝并提示格式错误 |
| **残余风险** | 边缘场景下的编码异常；可忽略 |

## 残余风险接受声明

1. **时间同步问题（R-01）**：共享窗口±1 分钟是 RFC 标准行为，无法进一步改进；若需更严格可缩小窗口但会降低可用性。

2. **熵源质量（R-02）**：`getrandom` 失败时不降级是合理决策；现代设备熵池充足。

3. **密钥内存保护（R-03）**：遵循行业标准（Android FLAG_SECURE、macOS 禁止截屏）；根/越狱下的内存访问是通用风险。

4. **SHA-1 哈希碰撞（R-06）**：RFC 6238 标准采用 SHA-1；HMAC 结构提供足够安全性；无需迁移到 SHA-256（会增加计算开销）。

**接受残余风险需项目发起人批准**。本风险评估已涵盖主要风险点，建议定期复查（季度或大版本发布前）。
